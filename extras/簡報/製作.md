# 簡報製作

> **選用。** 跟四份文件體系**沒有依賴關係**，可以單獨裝。
> **預計耗時**：選路線 5 分鐘，安裝 5 分鐘。
> **前提**：無。但要跟 [../圖表工具.md](../圖表工具.md) 搭配使用（圖歸圖、排版歸排版）。
>
> ⚠️ **Route A（frontend-slides）是 Claude Code 專屬**（它是 Claude Code plugin）。
> `工具/` 底下的 Python 出片腳本與 [規劃.md](規劃.md) 的整套 SOP **兩種工具都能用** ——
> 那才是這一包的主要價值。對照表見 [../README.md](../README.md)「哪些在 Codex 下也能用」。

## 0. 先回答一個常見誤會：diagram-design 不做簡報

diagram-design 有 `slide-16x9`、`slide-4x3` 兩個尺寸預設，很容易讓人以為它能做簡報。

**它不能。** 那兩個預設的意思是「產一張**尺寸適合貼進投影片**的圖」，
一次一張、一張一檔。它沒有頁次、沒有母片、沒有翻頁。

| 你要的 | 用什麼 |
|---|---|
| 一張架構圖／流程圖，要貼進投影片 | **diagram-design** → [../圖表工具.md](../圖表工具.md) |
| 一份 20 頁、可以站上去講的簡報 | **本文的工具** |

兩者是**分工不是取代**：diagram-design 出圖，簡報工具排版。第 4 節講怎麼接。

## 1. 選路線：一個問題就決定了

> ⭐ **先過 [規劃.md](規劃.md) 的兩道閘門，再回來選工具。**
> 「開場目的不明確、資訊太雜、最後還要再修一輪」**不是工具問題** ——
> 換工具治不了它，換的只是同一份雜訊的外觀。

> ## ⭐ **交出去的東西必須是 `.pptx` 嗎？**

這個問題決定一切，先答它。

```
必須交可編輯的 .pptx（協作者要接手改內容，或你自己還要一直改）
    └─→ 路線 C：從「大綱」直接出 pptx，之後在 PowerPoint 裡完稿
        → [規劃.md](規劃.md) 第 5 節

交 HTML／PDF 就好，或簡報是你自己上台講
    ├─→ 想要「好看、有設計感、開箱即用」 → 路線 A：frontend-slides ⭐ 本工具包選定
    └─→ 想要「原始碼是純 Markdown、進 git、diff 得出來」 → 路線 B：Marp
```

> ⭐ **2026-08-27 改寫了路線 C。**
> 原本這裡寫「沒有免費且可靠的『HTML → 可編輯 pptx』路徑」——
> 那句話本身沒錯，但它讓人以為「可編輯 pptx」整條路都不通。
> **不通的是「HTML → pptx」這個方向**，不是 pptx 本身：
> 從**大綱**直接生 pptx 是通的，而且零額外安裝就有一條（PowerPoint 自己的大綱匯入）。
> 所以路線 C 不再是「老實用 PowerPoint 手工做」，而是
> [規劃.md](規劃.md) 第 5 節的兩條出片路線。

### 三條路線比較

| | **A. frontend-slides** ⭐ | **B. Marp** | **C. 官方 pptx skill** |
|---|---|---|---|
| 是什麼 | Claude Code 外掛（skill） | Markdown → 投影片的工具鏈 | Anthropic 官方文件技能 |
| 原始碼形態 | 單一 HTML 檔 | 純 Markdown（`.md`） | 產生器腳本 |
| 產出 | 自帶樣式的單一 HTML | HTML / PDF / PPTX / 圖片 | 真正的 `.pptx` |
| 授權 | **MIT** | **MIT** | ⚠️ **Proprietary**（同一個 repo 其他 skill 是 Apache 2.0，這四個文件技能不是） |
| 額外安裝 | **核心路徑零安裝** | Node.js ≥ 18（`npx` 即可） | npm 的 pptxgenjs（建檔用）；⚠️ LibreOffice ＋ Poppler 只用在縮圖與驗證 |
| 受管電腦 | ✅ | ✅（Edge 已內建，見 3.2） | 🔶 建檔裝得起來，**驗證步驟裝不起來** |
| 熱門度（2026-08-26 查得） | 約 28k ★ | 約 12k ★ | — |
| 進 git 好不好 | 一個大 HTML，diff 難讀 | ✅ 最好 | 中 |

### 為什麼**不**推薦官方 pptx skill

兩個各自都足以否決的理由：

1. **授權是 Proprietary，不是開源。** 這個工具包的目的是**傳給協作者或合作對象** ——
   在說明文件裡叫別人去裝一個授權條款要另外讀的東西，是把問題丟給下一個人。
2. **它的完整流程要 LibreOffice（`soffice`）與 Poppler（`pdftoppm`）兩個外部執行檔。**
   受管電腦沒有本機管理員權限，這兩個裝不起來，要另外申請。

> ## ⚠️ **理由 2 在 2026-08-27 查證後更正過**
>
> 原本這裡寫「它要 LibreOffice 與 Poppler」，語氣是「所以整個裝不起來」。
> **實際上：建 pptx 不需要那兩個。** 它建檔用的是 npm 的 `pptxgenjs` 與原生 OOXML；
> `soffice`／`pdftoppm` 只用在**縮圖與檔案驗證**這兩個可選步驟。
>
> 結論沒有變（還是不收），但**理由要誠實**：擋掉它的是**理由 1 的授權**，
> 而理由 1 自己就足以否決。把「裝不起來」當主要理由是錯的，
> 那會讓下一個人在授權變了之後仍然不敢用。

> 這不是說它不好 —— 它產的是**真正可編輯的 pptx**。
> 而那件事現在有免費的做法了：見 [規劃.md](規劃.md) 第 5 節的兩條出片路線
> （其中一條零安裝，用 PowerPoint 自己的大綱匯入）。

## 2. 路線 A：frontend-slides ⭐ 本工具包選定的主線

上游專案：https://github.com/zarazhangrui/frontend-slides （MIT）

**這是本工具包選定的主線，沒有特殊理由就走這條。** 三個理由：

| 理由 | 說明 |
|---|---|
| **安裝方式跟 diagram-design 一模一樣** | 都是 `/plugin marketplace add` ＋ `/plugin install`。學一次會兩個，交接時也只要講一次 |
| **核心路徑零額外安裝** | 產 HTML 簡報不需要 Python、不需要 build step、不需要 npm 相依 |
| **MIT 授權** | 可以直接寫進交接文件叫協作者去裝，不用先讀授權條款（見第 1 節為什麼這條是硬判準） |

### 2.1 安裝

本文對照的版本：**2.1.0**（2026-08-26 實裝驗證）。

在 Claude Code 對話裡輸入這兩行：

```text
/plugin marketplace add https://github.com/zarazhangrui/frontend-slides
/plugin install frontend-slides@frontend-slides
```

也可以在終端機用 CLI 裝（不必先進對話）：

```bash
claude plugin marketplace add https://github.com/zarazhangrui/frontend-slides
claude plugin install frontend-slides@frontend-slides
claude plugin list                      # 應該看到 frontend-slides 且 Status 是 enabled
```

裝完**手動打開自動更新**：`/plugin` → **Marketplaces** → **frontend-slides** → **Enable auto-update**。
（原因見 [../圖表工具.md](../圖表工具.md) 第 2 節 —— 第三方 marketplace 預設關閉自動更新，而且不會提示。）

> ⚠️ **自動更新的開關只有互動介面裡有**，CLI 沒有對應指令。
> 不想開的話，之後手動拉：`claude plugin marketplace update frontend-slides`。

不想用外掛機制的話也可以直接 clone —— 這個 repo 的根目錄放了一份 `SKILL.md`，
就是為了這條路：

```bash
git clone https://github.com/zarazhangrui/frontend-slides.git ~/.claude/skills/frontend-slides
```

> **裝完要重開 session** 才吃得到（見 [ClaudeCode環境.md](../../setup/ClaudeCode環境.md) 第 4 節）。

### 2.2 怎麼觸發

| 裝法 | 打什麼 |
|---|---|
| 外掛（上面兩行裝的） | **`/frontend-slides:frontend-slides`** |
| clone 到 `~/.claude/skills/` | `/frontend-slides` |
| 兩者皆可 | 直接用自然語言：**「幫我把 `doc/DESIGN.md` 做成 10 頁簡報」** |

格式是 `/<外掛名>:<skill 名>`，兩段剛好同名所以看起來像講了兩次 —— 沒打錯。

> **平常直接講話就好。** 只有「講了但感覺它沒用到那個工具」或「有兩個工具都可能符合」
> 時才需要改打斜線指令 —— 為什麼會漏叫、斜線指令怎麼打，見
> [ClaudeCode環境.md](../../setup/ClaudeCode環境.md) 5.2 與 5.3。

### 2.3 它實際會跑的七個階段

**第 2 階段是它跟其他工具最不一樣的地方。**

| 階段 | 發生什麼 |
|---|---|
| **0 判斷模式** | 從零做，還是轉換現成的 PPT |
| **1 內容探索** | 你給文字、圖片或 `.pptx`。有給圖的話它會先評估怎麼用 |
| **2 ⭐ 風格探索** | **直接產三個視覺預覽讓你挑**，不是叫你用形容詞描述你要什麼 |
| **3 產出** | 照選定風格產完整簡報。沒給圖的話用 CSS 生成視覺（漸層、圖形、紋理），這是它正式支援的路線，不是退而求其次 |
| **4 PPT 轉換** | 只有走轉換模式才會經過 |
| **5 交付** | 產出單一 HTML，瀏覽器打開 |
| **6 分享與匯出**（選用） | PDF 匯出、Vercel 部署。⚠️ 後者會上傳內容，見 2.4 |

第 2 階段值得特別講：多數簡報工具要你先講清楚「我要簡約專業的科技感」，
然後產出一個你不要的東西。**看圖挑，比用形容詞描述準得多。**

隨附 **34 套版型**與三支腳本（`export-pdf.sh`、`deploy.sh`、`extract-pptx.py`）——
腳本對應的就是 2.4 那三個可選功能。

### 2.4 產出與可選功能

產出是**單一自帶樣式的 HTML 檔**：inline CSS ＋ inline JS，沒有 npm 相依、沒有 build step。
用瀏覽器開就能全螢幕播放。

| 想多做什麼 | 要裝什麼 | 建議 |
|---|---|---|
| 匯入現成的 `.ppt` / `.pptx` 當素材 | Python 的 `python-pptx`（見 [Python環境.md](../../setup/Python環境.md)） | 有需要再裝 |
| 匯出 PDF | Node.js（Playwright 會自動裝） | ⚠️ **先試瀏覽器的「列印 → 另存 PDF」**，多數情況就夠了 |
| 產一個可分享的網址 | Node.js ＋ Vercel 帳號 | ⚠️ **這會把簡報內容上傳到外部服務。非公開資料不要用這條** |

> ⚠️ **PDF 匯出只是靜態快照，動畫不會保留。** 動畫只在瀏覽器播放時看得到。
> 這代表：**要交 PDF 的話，一開始就別依賴動畫傳達資訊。**

### 2.5 第一次跑：實際怎麼餵它

**不要開一個空白對話就說「幫我做簡報」。** 它會先問你一輪你還沒想清楚的問題。
先把三件事準備好，再開口：

| 準備什麼 | 為什麼 |
|---|---|
| **內容從哪來** | 一份現成的 `.md`、一段貼上的文字，或一個舊的 `.pptx`。**有原料比沒原料快十倍** |
| **講給誰聽** | 主管、工程師、客戶 —— 這決定用字與深度，跟第 1 節的路線選擇無關 |
| **幾分鐘 / 幾頁** | 沒講的話它會產出比你需要的更多頁 |

三個實際講得出來的例子：

```text
把 doc/DESIGN.md 做成一份 10 頁的簡報，講給不懂技術的主管聽，重點放在「要驗證什麼假設」

把這份會議記錄做成 5 頁的進度回報，每頁一個重點，不要動畫

拿這個舊的 .pptx 當素材，重做成同樣內容但視覺一致的 HTML 簡報
```

> ⭐ **裝了 A 組的話，最好的原料就在 `doc/` 裡。**
> `DESIGN.md` 的「要驗證的假設」拿來當簡報骨架、`decisions/` 拿來講「為什麼選這條路」——
> 那些內容當初就是為了「三個月後還說得清楚」而寫的，正好是簡報要的東西。
> 這也是 A 組與 B 組唯一會碰到彼此的地方：**B 組讀 A 組的產出，但不依賴它。**

### 2.6 挑風格那一步不要亂按

第 2 階段它會產三個視覺預覽讓你挑。**這一步決定後面全部的樣子，改起來不便宜。**

- 挑之前先想清楚**受眾**：對外提案跟內部進度回報要的東西不一樣
- 三個都不滿意就說「都不要，再給我三個，往 <某方向> 走」—— **不要勉強選一個再慢慢改**
- 選定之後才給完整內容，讓它一次產完

產出是**單一 HTML 檔**。交出去就是交那個檔，對方用瀏覽器打開就能看，
不需要裝任何東西 —— 這是它跟 pptx 路線最大的體感差異。

## 3. 路線 B：Marp

上游專案：https://github.com/marp-team/marp （MIT）

**什麼時候選這條**：簡報的原始碼要**進版控、要 diff 得出來、要跟文件放在一起**時。
Marp 的來源就是一個 `.md` 檔，和 `doc/` 底下那四份是同一種東西。

### 3.1 不用全域安裝

```bash
npx @marp-team/marp-cli@latest 簡報.md                # → HTML
npx @marp-team/marp-cli@latest 簡報.md --pdf          # → PDF
npx @marp-team/marp-cli@latest 簡報.md --pptx         # → PPTX（見 3.3 的警告）
```

需要 **Node.js ≥ 18** —— 這個移植包本來就要求它（收工檢查 hook 是 Node 寫的），
所以裝過移植包的話這條**沒有新的前置需求**。

`npx` 是「跑一次，不全域安裝」，在不能 `npm install -g` 的環境特別有用。

### 3.2 匯出需要一個瀏覽器 —— 但你已經有了

PDF、PPTX、圖片匯出都需要本機有 Chrome、Edge 或 Firefox 其中之一。
偵測順序是 **chrome → edge → firefox**。

> ✅ **Windows 11 內建 Edge，所以這條實務上不用額外做任何事。**
> 這是 Marp 相對於官方 pptx skill 的關鍵差異：後者要的 LibreOffice 與 Poppler
> **不是**任何 Windows 內建的東西。

指定路徑：`--browser-path`。

### 3.3 ⚠️ Marp 的 PPTX 是圖片，不能編輯

**這一節是選路線 B 之前必讀。**

`--pptx` 產出的每一頁**是一張預先算好的背景圖**。開起來是 PowerPoint 沒錯，
但**裡面的字改不了、也選不起來**。

有一個實驗性的 `--pptx-editable` 可以產出可編輯的文字與圖形，但它：

- 需要瀏覽器**再加上 LibreOffice Impress** —— 又回到路線 C 的那個安裝問題
- 遇到複雜主題會產出不完整的結果

> **所以：如果對方要的是「可以自己改字的 pptx」，Marp 的 `--pptx` 不算數。**
> 誠實的答案在第 1 節的路線 C。

### 3.4 VSCode 即時預覽（選用）

外掛 **Marp for VS Code**（`marp-team.marp-vscode`）可以邊寫邊看。

> ⚠️ **受管電腦通常不能自行安裝 VSCode 外掛**，需要請管理員協助。
> 裝不了也沒關係 —— `npx ... 簡報.md` 產出 HTML 用瀏覽器開，效果一樣，只是慢一點。
> 或用你已經有的 **Live Server** 外掛開產出的 HTML（見 [../VSCode外掛.md](../VSCode外掛.md)）。

## 4. 跟 diagram-design 怎麼接

**簡報裡的圖，不要用簡報工具畫。** 分工是這樣：

```
內容（文字）  ──┐
                ├─→ 簡報工具（frontend-slides / Marp）→ HTML / PDF
圖 ─ diagram-design → PNG ──┘
```

出圖時把轉盤設成簡報用的值：

```text
/diagram-design:diagram-design --size=slide-16x9 --detail=simplified --format=png
```

| 轉盤 | 簡報用什麼 | 為什麼 |
|---|---|---|
| `--size` | `slide-16x9` | 1280×720 版面，輸出 2560×1440（2 倍圖，投影不糊） |
| `--detail` | `simplified`（≤7 節點） | 台下的人只有幾秒。**塞不下不是尺寸問題，是節點太多** |
| `--format` | `png` | PNG 是透明背景，貼到任何底色都不會有白框 |

PNG 匯出要 Playwright，卡住的話看 [../圖表工具.md](../圖表工具.md) 第 6 節的防火牆說明。

> **一個實用的替代路徑**：`--format=svg`（零依賴），frontend-slides 的 HTML 簡報
> 可以直接內嵌 SVG。走 HTML 這條路的話，PNG 根本不需要。

## 5. 踩坑清單

| 坑 | 現象 | 原因 | 解法 |
|---|---|---|---|
| **以為 diagram-design 能做簡報** | 找不到怎麼加第二頁 | 它一次產一張圖 | 第 0 節 |
| **Marp 的 pptx 交出去被抱怨改不了** | 對方說「字選不起來」 | `--pptx` 每頁是一張背景圖 | 第 3.3 節。要可編輯就別走這條 |
| **裝了官方 pptx skill 才發現要 LibreOffice** | 跑到一半說找不到 `soffice` | 那個 skill 依賴外部執行檔 | 第 1 節，改走 A 或 B |
| **自動更新沒開** | 停在安裝當天的版本 | 第三方 marketplace 預設關閉 | 第 2.1 節 |
| **PDF 匯出後動畫沒了** | 交出去的檔跟預覽不一樣 | PDF 是靜態快照 | 別讓動畫承載資訊 |
| **用 Vercel 分享非公開簡報** | 內容上了公開網路 | 那條路會上傳到外部服務 | 非公開資料不要用。交 HTML 檔本身 |
| **投影片上的圖看不清楚** | 台下看不懂 | `--detail` 開太高 | 降到 `simplified`，一張圖只講一件事 |
| **一開始就出 HTML，後來被要求交可編輯的 pptx** | 又要轉一次，而且文案正本變成兩份 | 先挑工具、後想交付形態 | [規劃.md](規劃.md) 5.1。先出 pptx 再出 HTML |
| **VSCode 外掛裝不了** | 受管電腦擋住 | 企業原則 | 改用 `npx` ＋ 瀏覽器，或 Live Server |

## 7. 這一節是給接手的人看的：為什麼是這三條

2026-08-26 掃過當時熱門的做法之後留下這三條，順便記下**沒選的**：

| 看過但沒收進來 | 為什麼 |
|---|---|
| **reveal.js / Slidev** | 兩個都好，但要 build step 或 dev server。跟「受管電腦、零安裝」的前提衝突。真的要用的話 frontend-slides 產的單檔 HTML 已經涵蓋多數需求 |
| **zl190/md-slides** | 是 Marp CLI 的薄包裝，本身沒加多少東西（2026-08-26 查得個位數星數），而且可選功能要 LaTeX（約 4GB）或 Gemini API key。直接用 Marp 就好 |
| **線上簡報產生器（Gamma 等）** | 要把內容貼上外部網站。非公開資料這條先天不通 |

### 2026-08-27 補掃：專門做 pptx 的那一批

上面那輪只掃「做整份簡報」的工具。這一輪補掃的是「**產可編輯 pptx**」這件事：

| 看過的 | 授權 | 為什麼收或不收 |
|---|---|---|
| **anthropics/skills** 的 `pptx` | ⚠️ **Proprietary** | 現在一行就裝得到（`/plugin marketplace add anthropics/skills`），但授權判準擋掉。詳見第 1 節那則更正 |
| **tristan-mcinnis/pptx-from-layouts-skill** | **MIT** | 只要 `python-pptx` ＋ `pydantic`，markdown 大綱 → 套範本母片版型。23 ★ 太薄不當主線，但**當成藍本**寫進了 [工具/outline-to-pptx.py](工具/outline-to-pptx.py) |
| **tfriedel/claude-office-skills** | 未標明 | 817 ★，官方公開前的社群復刻。要 LibreOffice ＋ Poppler ＋ Pandoc，**兩條判準都不過** |
| **pptxgenjs**（npm） | **MIT** | 官方 skill 內部就用它。短處是**不套既有範本母片**，只能從零建版面 —— 所以自寫腳本選了 python-pptx |

結論：**不裝現成的 skill，自己寫一支小腳本。** 理由是那兩條判準 ——
自己寫的腳本沒有授權問題，而且只依賴一個純 Python 套件。
流程與腳本在 [規劃.md](規劃.md)。
