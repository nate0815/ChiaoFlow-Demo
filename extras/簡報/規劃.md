# 簡報規劃

> **選用。** 跟四份文件體系**沒有依賴關係**，可以單獨用。
> **預計耗時**：場合卡 10 分鐘，大綱表 30–60 分鐘，出片 10 分鐘。
> **前提**：無。**工具怎麼裝在 [製作.md](製作.md)，這份只管內容。**
> **治什麼病**：AI 掃得完整個 repo、簡報也產得出來，但**開場沒把目的講明確、
> 無效資訊比預期多，整份做完之後還要再修一輪。**

---

## 0. 它是什麼、不是什麼

| | |
|---|---|
| ✅ **是** | 一套**內容規劃流程**：先定場合，再定每頁講什麼，**最後才出檔案** |
| ✅ **是** | 三個閘門 ＋ 一份可複製的範本（[.](.)） |
| ❌ **不是** | 工具安裝說明 —— frontend-slides／Marp 怎麼裝在 [製作.md](製作.md) |
| ❌ **不是** | 視覺設計指南 —— 挑風格那一步在 [製作.md](製作.md) 2.6 |
| ❌ **不是** | 給「隨手做張投影片」用的 —— 5 頁以下的例行同步不用走這套 |

**分界一句話**：`簡報製作.md` 管**用什麼做**，這份管**做什麼、砍什麼、什麼時候做**。

**五個階段**：① 出大綱 → ② 出內容 → ③ 出視覺 → ④ 整合成 pptx → ⑤ 人工手修。
⭐ **順序不能顛倒**，理由見 [README.md](README.md)。整合那一步在第 5.4 節。

## 1. 為什麼「掃完整個 repo」反而讓簡報更雜

先講一個實際發生過的例子，因為它把三個症狀一次演完。

一份 28 頁的簡報，內容全部有出處、每頁都守住排版規矩，
交出去之後得到的回饋是四個字：**「太多且太雜」**。

**當下的誤診是「字太多」。** 於是逐頁刪字 —— 量出來只省了 **5%**。

真正的原因是：**那 28 頁是為「完整導覽」寫的，而實際場合是「10 分鐘的提案」。**
場合不對，每一頁都合理，整份還是錯的。最後的處置不是刪字，是**另開一份 12 頁的提案版**。

### 三個症狀，三個會誤診的方向

| 症狀 | 你會誤診成 | 真正的根因 |
|---|---|---|
| 開場沒把目的講明確 | 「開場文案要再寫好一點」 | **開場講的是「內容是什麼」，不是「今天要你回答什麼」** —— 因為後者從來沒被寫下來 |
| 無效資訊比預期多 | 「字太多，該精簡」 | **沒有先定義「不討論什麼」**，所以沒有任何一頁砍得掉 |
| 最後還要修一輪 | 「AI 做得不夠好」 | **唯一的人審點在成品之後** —— 回饋成本被推到最貴的位置 |

### 核心：缺的不是資料，是篩選判準

你把整個 repo 給 AI，它會傾向**完整覆蓋** —— 這不是它的缺點，
而是**「哪些不該講」推不出來**：那個答案不在 repo 裡，在場合裡。

> ⭐ **資料完整度不等於簡報品質。**
> 你補的每一份參考文件，都同時擴大了「可以講的東西」的範圍。
> 沒有場合卡的話，補資料只會讓簡報更雜。

所以這份 SOP 的全部內容就是：**把場合寫下來，並且寫在動手之前。**

## 2. ⭐ 閘門一：場合卡（不填完不要開始）

> ## ⭐ **這一版是為誰寫的？要對方回答什麼？**

這兩個問題決定後面每一次取捨，先答它們。**答案要打成文字**，
想在腦袋裡不算 —— 沒寫下來的東西，AI 讀不到，你自己過三天也會忘。

範本在 [範本/大綱.md](範本/大綱.md) 檔頭，六欄：

| 欄 | 填什麼 | 為什麼這欄不能省 |
|---|---|---|
| **對象** | 一個具體的人或角色（老闆、客戶端 PM、新進工程師） | 「給大家看」等於沒填。用字深度由這欄決定 |
| **時間** | 幾分鐘 | 直接換算成頁數上限，見下表 |
| **要對方回答的** | **最多兩題**，用問句寫 | ⭐ **這是後面所有取捨的唯一判準。** 三題以上代表你其實要開兩場會 |
| **形式** | 你上台講／對方自己讀／邊看 demo 邊聽 | 決定講稿與頁面的分工。對方自己讀的話，頁面要吃下講稿 |
| **不討論** | 明確列出**這次不碰**的題目 | ⭐ **不寫這欄，後面就砍不掉任何東西。** 砍頁的依據全在這裡 |
| **成功標準** | 散會時你希望發生什麼（拍板／給下一步／排下次） | 沒有這欄，簡報會變成「講完就好」 |

### 頁數預算：先算上限，再開始寫

| 場合 | 時間 | 頁數 | 每頁 |
|---|---|---|---|
| 進度同步 | 5 分鐘 | **4–6 頁** | 50–75 秒 |
| 提案／要對方拍板 | 10–15 分鐘 | **8–14 頁** | 60–90 秒 |
| 完整導覽／教學 | 30 分鐘以上 | 20–30 頁 | 60–90 秒 |
| 只給人自己讀（不上台） | — | 不受此表限制 | 改用閱讀密度，見 4.1 |

算式就一句：**頁數 ≈ 分鐘數 × 1**（提案場合）。10 分鐘就是 10 頁上下，不是 28 頁。

> ⚠️ **一個場合只能有一份簡報。**
> 同一份內容要給兩個場合，就**開兩份**，不要做一份「兼顧」的 ——
> 兼顧的那份會同時對兩邊都太雜。
> 上面那個例子最後的處置就是這樣：28 頁那份**一個字都沒改**，另開 12 頁。
> 舊版留著，之後還對比得出來取捨了什麼。

## 3. ⭐ 閘門二：逐頁大綱表（人審點只有這一個）

場合卡過關之後，**先寫大綱表，不要碰任何簡報工具。**
這一步的產出是純文字的一張表，改起來零成本 —— 這正是它存在的理由。

一頁一列：

| 欄 | 填什麼 |
|---|---|
| **頁** | 頁次 |
| **主張** | ⭐ **一個完整句子**，就是你希望台下記住的那句話 |
| **服務哪一題** | 場合卡「要對方回答的」①或②。**填不出來的頁，砍掉或併頁** |
| **證據** | 數字、截圖、圖表，以及它的**出處**（哪份文件的哪一節） |
| **視覺** | 圖／截圖／純文字。這一欄只寫「要什麼」，不寫「長什麼樣」 |
| **秒** | 打算講幾秒。**加總要對得上場合卡的時間** |

### 3.1 主張欄必須是完整句子

這是整份 SOP 裡**效果最好的單一條規則**，因為名詞短語可以蒙混過關，句子不行。

| ❌ 名詞短語（過不了） | ✅ 完整句子（可以） |
|---|---|
| 「兩條內容線的節奏」 | 「兩條線收滿的長度差 5–8 倍，這是刻意的手段，不是還沒調平衡」 |
| 「系統架構」 | 「這套架構的三個模組可以各自替換，所以改一個不會動到另外兩個」 |
| 「目前進度」 | 「十個項目有八個完成，卡住的兩個都在等外部回覆」 |

寫不出句子，代表**這一頁你其實還不知道要講什麼**。這時候只有兩條路：想清楚，或砍掉。

### 3.2 開場三頁的固定骨架

「開場目的不明確」這個病，靠固定骨架就治掉了：

| 頁 | 講什麼 | 常見的錯誤 |
|---|---|---|
| **1 封面** | **這場的目的** ＋ 一句話定位 | ⛔ 拿來講內容機制、拿來塞規格 —— 那些後面有位置 |
| **2 提案／結論** | 你要說的那一句話，**先講結論** | ⛔ 從背景講起，結論放最後 |
| **3 今天要你回答什麼** | 把場合卡「要對方回答的」①②**直接印在頁面上** | ⛔ 只在口頭講，或完全不提 |

> ⭐ **封面講的是「這場的目的」，不是「內容是什麼」。**
> 這一條看起來廢話，但實務上最常錯的就是它 —— 因為內容是你熟的，目的是你沒寫下來的。
> 第 3 頁那一頁也不要省：印出來，對方才知道該在什麼時候插話。

### 3.3 這張表交出去給人看

> ⭐ **這是全流程唯一需要別人看的檢查點。** 只看這張表，不要給視覺。

給人看的時候只問一句：**「有哪一頁你覺得不用講？」**
在這個階段砍一頁的成本是刪一列文字；在成品階段砍一頁要重排版面、重出檔案、重對數字。

## 4. ⭐ 閘門三：密度檢查（出片前逐頁跑）

大綱表定案之後，**逐頁**跑完這一節才出檔案。

### 4.1 三條硬規矩

1. **每頁只有一個主張**；內文最多 **4 點**、每點不超過 **20 字**
2. **不出現檔名、路徑、程式碼、函式名、版號流水帳、內部編號** —— 這一版沒有例外
3. **中性立場**：不提另一版做法、不做 A／B 優劣比較（除非場合卡就是要比）

> 這三條是實戰打出來的，不是憑空定的。
> 「對方自己讀」的場合，第 1 條放寬成 6 點 —— 因為頁面要吃下講稿；
> 「你上台講」的場合就守 4 點，多的話講稿吃掉。

### 4.2 數字要有出處，而且要標清楚是哪一種

在大綱表的證據欄之外，另外開一張「**已核對過的數字**」清單，
把整份簡報用到的數字集中列一次。理由很實際：同一個數字出現在三頁而彼此不一致，
是最傷信任的錯，而且**逐頁看看不出來**。

> ⚠️ **「現值」與「設計值」一定要標開。**
> 原型跑出來的數字（掉落率、次數、時間）如果沒標「原型值」，會被當成承諾。
> 這一行字不能省，也不能因為版面太滿就刪。

### 4.3 逐頁問三句

- 這頁服務場合卡的哪一題？（答不出來 → 砍或併）
- 這頁的主張是句子嗎？（不是 → 想清楚或砍）
- 這頁有沒有踩到「不討論」欄位？（有 → 砍）

## 5. 出片：大綱表 → pptx（三條路線）

### 5.1 為什麼不一開始就出 HTML

HTML 簡報好看，但它有兩個代價，而且都要到後期才會痛：

| 代價 | 實際發生什麼 |
|---|---|
| **文案正本會變成兩份** | 文案同時存在大綱 `.md` 與 HTML 檔裡，要手動同步。**改錯邊不會報錯**，只會改不到你要改的那份 |
| **交出去的人改不動** | 對方要改一個字得動 HTML。要交可編輯檔的話，最後還是得再轉一次 |

所以順序反過來：**先出 pptx 當工作稿**，之後所有調整都在 PowerPoint 裡做。
HTML 什麼時候才值得出，見 5.4。

### 5.2 路線甲：PowerPoint「從大綱插入投影片」⭐ 零安裝

叫 AI 把大綱表轉成**用 tab 縮排的 `.txt`**（不縮排的行變成頁標題，縮排的變成該頁條列），
然後在 PowerPoint 裡：

```text
常用 → 新增投影片「旁邊的箭頭」→ 從大綱插入投影片 → 選那個 .txt
```

拿到的是**套用當前範本母片、真正可編輯**的骨架 —— 大綱檢視裡就能繼續改。
吃 `.txt`、`.rtf`、`.docx`、`.doc`，最多 5 層階層。
`.docx` 要用**標題樣式**（標題 1 = 頁標題，標題 2 = 條列）——
套「內文」樣式的段落**不會被帶過去**，而且不會有任何提示。

| ✅ 給你 | ❌ 不給你 |
|---|---|
| 標題 ＋ 條列層級 | 圖與截圖 |
| 自動套用範本母片 | 講者備忘 |
| 零安裝、零套件 | 「主張」這種非條列欄位 |

**適用**：20 頁以內、以文字為主、圖不多的場合。缺的三樣手動補。

### 5.3 路線乙：`outline-to-pptx.py`（要圖與講者備忘就走這條）

腳本在 [工具/outline-to-pptx.py](工具/outline-to-pptx.py)，讀大綱 `.md` 直接產 pptx：
標題／主張／條列／圖片／講者備忘一次帶進去，也可以套你自己的範本檔。

```bash
python extras/簡報/工具/outline-to-pptx.py 大綱.md -o 簡報.pptx
python extras/簡報/工具/outline-to-pptx.py 大綱.md -o 簡報.pptx --template 既有範本.pptx
```

要一個 `python-pptx`（純 Python，**不需要 LibreOffice、不需要管理員權限**）——
裝法與注意事項見 [../../setup/Python環境.md](../../setup/Python環境.md)。

> ⚠️ **兩條路線都是單向輸出。** 在 pptx 裡改的東西**不會回到大綱 `.md`**。
> 出片之後就以 pptx 為正本，大綱表退位成「當初怎麼決定的」紀錄 —— 不要維護兩份。

### 5.4 ⭐ 路線丙：`themed-pptx.py`（帶視覺的最終交付）

**這是整條流程的第 ④ 步。** 上面兩條路線出的是樸素 pptx（套當前範本母片）；
這條出的是**帶著你選定視覺的 pptx**，而且文字仍然在真正的 placeholder 裡 —— 改得動、大綱檢視看得到。

```bash
python extras/簡報/工具/themed-pptx.py 大綱.md 簡報.pptx
```

它做的事：

| 元素 | 怎麼實作 |
|---|---|
| 紙色底、製圖網格、四角定位十字 | **一張底圖**（`工具/assets/bg-grid.png`，全部頁面共用一張） |
| 區段識別條、重音底線、刻度尺 | 原生形狀 —— 可以搬、可以刪 |
| 主張與條列 | **真正的 placeholder** |
| 圖 | 內嵌圖片；沒有條列的頁自動改成整頁寬 |

> ⛔ **不要試著「把 HTML 轉成 pptx」。** HTML 的視覺是 CSS，轉不成 PowerPoint 的形狀與文字框。
> 市面上的轉換工具產出的是**每頁一張圖片**，字選不起來、改不動 —— 對「人工手修」等於沒用。
> 這條路線不做轉檔，它**讀同一份大綱、直接畫出**同一套視覺。

#### ⚠️ 字型：只用目標機器已經有的

視覺設計常用的 Google Fonts（Geist、Instrument Serif 之類）**多數機器沒裝**。
這份 pptx 的用途是**交給協作者改**，所以字型只挑本機已有的
（例如 `Noto Sans TC` ＋ `Cascadia Code`）—— 對方打開才不會變成替代字型、版面才不會跑掉。

跑之前先確認：

```powershell
Get-ChildItem "$env:WINDIR\Fonts","$env:LOCALAPPDATA\Microsoft\Windows\Fonts" -Include *.ttf,*.otf,*.ttc -Recurse |
  Select-Object -ExpandProperty Name | Sort-Object
```

#### ⚠️ 要上 Google Slides 的話

pptx 匯進 Google Slides 之後：**形狀、文字框、底圖、內嵌圖都會過去**，
但**字型會被替換成 Google Fonts 裡有的**。`Noto Sans TC` 過得去，等寬字通常過不去。

所以匯入之後要檢查兩件事：**中文有沒有掉字型**、**等寬的頁碼與標籤有沒有跑版**。

### 5.5 HTML 什麼時候才值得另外出

> ## ⭐ **預設只出 pptx。** 四個情況才另外出一份 HTML。

| 情況 | 為什麼 |
|---|---|
| 要交一份**好看**的版本給人自己讀 | 已經被 5.4 的路線丙解掉了 —— 這種情況**不需要** HTML |
| 你要**上台播**，而且動態能幫到理解 | pptx 的動畫難維護，HTML 的進場動畫是 CSS |
| 要一個**可分享的網址** | ⚠️ 非公開資料不要走 Vercel，見 [製作.md](製作.md) 2.4 |
| 對方**不裝任何軟體**就要能開 | 單檔 HTML，瀏覽器打開就是 |

```bash
python extras/簡報/工具/html-deck.py 大綱.md extras/簡報/工具/deck-shell.html 簡報.html
```

怎麼挑風格見 [製作.md](製作.md) 第 2 節。大綱早就定案了，
所以 frontend-slides 的內容探索階段可以直接餵大綱表 —— 只有風格探索那一步需要你選。

### 5.6 ⚠️ 四件實跑過才知道的事

| 事情 | 說明 |
|---|---|
| **所有產出都從同一份大綱出** | 不要從 pptx 轉 HTML，也不要反過來。**大綱是唯一正本** |
| **配色要跟圖對齊** | 簡報裡的圖如果是淺色系，別選暗底風格 —— 淺色圖放在暗底上會像貼上去的白方塊。反過來也一樣 |
| **細節多的圖在任何 16:9 版面都會太小** | 這跟版面無關，是比例問題。⭐ **把圖的畫布加寬不會讓文字變大，只會讓它相對變小 —— 唯一的槓桿是減少節點** |
| **有圖的頁條列要砍到 4 點** | 圖占右半邊、內文縮到約一半寬。這是圖的代價，不是 bug |

## 6. 怎麼餵 AI：把 `doc/` 變成大綱的路由表

裝了 A 組的話，原料就在 `doc/` 裡。但**不是每一份都該進簡報** ——
這張表就是路由，順便就是「不討論」欄位的來源：

| 來源 | 進簡報的哪裡 |
|---|---|
| `DESIGN.md` 的**要驗證的假設** | ⭐ 場合卡的「要對方回答的」，以及第 3 頁 |
| `DESIGN.md` 的一句話說明 | 封面副標 |
| `DESIGN.md` 的**明確不驗證什麼** | ⭐ 場合卡的「不討論」 |
| `PLAN.md` 的核心判斷、為什麼不用某方案 | 「為什麼選這條路」那幾頁 |
| `decisions/`（`status: 生效` 的） | 同上，一則決策通常剛好一頁 |
| `DEVLOG.md` 的待決問題 | 「不討論」，或最後一頁的下一步 |
| `gotchas/` | ⛔ 通常**不進**簡報（除非場合就是要講風險） |
| `TECH.md` | ⛔ **幾乎全部不進**簡報 —— 那是實作細節，踩到硬規矩第 2 條 |

實際講得出來的一句話：

```text
讀 doc/DESIGN.md 與 doc/decisions/，照 extras/簡報/規劃.md 的流程做：
先產場合卡讓我確認，過了再產逐頁大綱表，我都同意之後才出 pptx
```

> ⭐ **關鍵是「讓我確認」那四個字。** 不講的話，AI 會一路做到成品 ——
> 那就退回本文第 1 節那三個症狀了。

## 7. 踩坑清單

| 坑 | 現象 | 原因 | 解法 |
|---|---|---|---|
| **一開始就出 HTML，後來要交 pptx** | 又要轉一次，文案正本變兩份 | 順序錯了 | 第 5.1 節。先 pptx 後 HTML |
| **逐頁刪字想解決「太雜」** | 刪半天只省 5% | 病灶在場合，不在字數 | 第 1 節。回頭填場合卡 |
| **一份簡報想兼顧兩個場合** | 兩邊都嫌雜 | 場合卡只能有一組答案 | 開兩份，舊那份不要改 |
| **主張欄寫成名詞短語** | 排版之後看不懂在講什麼 | 名詞短語蒙混得過去 | 第 3.1 節，改寫成句子 |
| **「要對方回答的」寫了三題以上** | 散會沒有結論 | 那其實是兩場會 | 砍到兩題，其餘進「不討論」 |
| **數字沒標「原型值」** | 被當成承諾 | 現值與設計值沒標開 | 第 4.2 節。那一行不能刪 |
| **`.docx` 大綱匯入後只有一頁** | 全部內容擠在一頁 | 沒套標題樣式 | 用標題 1／2，或改用 tab 縮排的 `.txt` |
| **在 pptx 改完又回去改大綱** | 兩份不一致 | 出片是單向的 | 第 5.3 節。出片後以 pptx 為正本 |
| **大綱過關就直接跳去挑視覺風格** | 風格選完才發現頁數要砍 | 跳過密度檢查 | 第 4 節先跑完 |

## 8. 完成檢查清單

### 8.1 規劃過關（出片之前）

- [ ] 場合卡**六欄都填了**，而且是打成文字的
- [ ] 「要對方回答的」**最多兩題**，用問句寫
- [ ] **「不討論」欄位不是空的**
- [ ] 頁數在場合卡的預算內（第 2 節那張表）
- [ ] 大綱表每一頁的**主張都是完整句子**
- [ ] 每一頁的「服務哪一題」都填得出來
- [ ] 秒數加總對得上場合卡的時間
- [ ] **大綱表已經給人看過**，並問過「有哪一頁不用講」

### 8.2 成品過關（出片之後）

- [ ] 第 1 頁講的是**這場的目的**，不是內容機制
- [ ] 第 3 頁把「今天要你回答什麼」**印在頁面上**
- [ ] 逐頁查過三條硬規矩（一主張／≤4 點 × 20 字／無檔名路徑函式名）
- [ ] 所有數字對過「已核對過的數字」清單，且**現值標了「原型值」**
- [ ] 交出去的檔案**文字選得起來、改得動**（用 PowerPoint 開一次確認）
- [ ] 講者備忘有帶進去（走路線乙的話）
- [ ] **知道出片是單向的** —— 之後改 pptx，不改大綱

### 8.3 視覺與整合過關（階段 ③④）

- [ ] 視覺是在**大綱定案之後**才開始選的，不是邊改內容邊做
- [ ] 風格的配色跟簡報裡的**圖同一個色系**（淺色圖不要配暗底）
- [ ] 所有產出**都從同一份大綱生成**，沒有互相轉檔
- [ ] 逐頁看過一次：沒有溢出、沒有重疊、圖沒有壓到頁腳
- [ ] 圖上的字**在實際尺寸下讀得到**（讀不到就是節點太多，不是版面問題）
- [ ] 字型只用目標機器已有的（要上 Google Slides 的話另見 5.4）
- [ ] 知道**手修之後就不能再重跑產生器**

## 9. 這一節是給接手的人看的

### 9.1 為什麼閘門在這三個位置

一句話：**閘門要卡在「改起來還便宜」的地方。**

| 階段 | 改一頁的成本 | 所以 |
|---|---|---|
| 場合卡 | 改一格字 | ⭐ 卡閘門 |
| 大綱表 | 刪一列 | ⭐ 卡閘門（唯一的人審點） |
| 密度檢查 | 改幾行字 | ⭐ 卡閘門 |
| 出片後 | 重排版面、重出檔案、重對數字 | ❌ 太貴，這裡不該再有大改 |

原本的流程只有最後那一格有檢查點，所以每次都在最貴的地方付錢。

### 9.2 為什麼這一輪不做 skill

[../README.md](../README.md) 定調過：**Extras 沒有自動化裝置**，
因為它是一次性產出，裝閘門沒有東西可以擋。這份 SOP 讓那句話變得沒那麼絕對 ——
場合卡與大綱表**確實有東西可以擋**（大綱沒過就不准出片）。

但這一輪刻意先不做，理由是**還沒跑過足夠多次**：
閘門的判準要先用手跑幾遍，才知道哪一條真的有效、哪一條只是好聽。

未來要做的話，該擋的是這兩件事：

1. 場合卡六欄沒填完 → 不准進大綱階段
2. 大綱表存在、且「服務哪一題」全部填滿 → 才准跑出片腳本
