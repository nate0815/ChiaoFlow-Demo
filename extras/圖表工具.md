# 圖表工具（diagram-design）

> **選用。** 這份跟四份文件體系**沒有依賴關係** —— 沒裝移植包也能單獨用它。
> 它治的是另一種病：**AI 產得出圖，但那張圖沒人想放進文件或簡報。**
> **預計耗時**：安裝 5 分鐘，品牌化再 5 分鐘。

> ⚠️ **這一份是 Claude Code 專屬**（diagram-design 是 Claude Code plugin）。
> 用 Codex CLI 的話沒有現成對應路線 —— 但[簡報](簡報/)的 SOP 與 Python 出片腳本
> 兩邊都能用，見 [README.md](README.md)「哪些在 Codex 下也能用」。

上游專案：https://github.com/cathrynlavery/diagram-design （MIT）
本文對照的版本：**2.6.6**（2026-08-26 安裝）。

## 0. 它是什麼、不是什麼

先把邊界劃掉，這一節省下的是後面兩小時的誤會。

| | |
|---|---|
| ✅ **是** | 一次產**一張**圖。輸出是自帶樣式的單一 HTML／SVG／PNG，無 build step、無外部資源、無 JavaScript |
| ✅ **是** | 讀 `.mmd`（Mermaid）或 `.drawio` 把它**重畫**成同一套設計系統的圖 |
| ❌ **不是** | 簡報工具。它有 `slide-16x9` 尺寸預設，那是「產一張貼進投影片的圖」，不是「產一份簡報」 |
| ❌ **不是** | Mermaid render 器。它**不執行** Mermaid，也不需要 Mermaid 環境 —— 它把 Mermaid 當成純文字讀進來 |

要做**整份簡報**看 [簡報/製作.md](簡報/製作.md)。兩者是分工：**diagram-design 出圖，簡報工具排版。**

要**圖能引用程式碼、而且引用會被驗證**，那是另一個工具 —— 見第 9 節的 archify。

## 1. 前置需求

| 你要做什麼 | 需要什麼 | 受管電腦裝得起來嗎 |
|---|---|---|
| 產圖（HTML／SVG） | 只要 Claude Code（見 [ClaudeCode環境.md](../setup/ClaudeCode環境.md)） | ✅ **零額外安裝** |
| 匯入 `.mmd` / `.drawio` | ＋ Python 3（見 [Python環境.md](../setup/Python環境.md)） | ✅ 可以 —— **單一使用者安裝不需要管理員權限** |
| 匯出 PNG | ＋ Python 的 Playwright | ⚠️ 會跳防火牆視窗，見第 6 節 |

> ## ⚠️ 匯入功能撞到的第一個坑通常不是安裝，是「哪一個 python」
>
> 上游文件寫的是 `python3 <skill-dir>/scripts/mermaid_extract.py`，
> 但在 Windows 上 `python` 與 `python3` **經常是兩個不同版本的直譯器**，
> 套件目錄也不相通。裝好了卻 `ModuleNotFoundError` 多半就是這個。
> **診斷與解法在 [Python環境.md](../setup/Python環境.md) 第 3 節。**

> **HTML 這條路完全零依賴，先走這條。** 產出的檔案用瀏覽器直接開就看得到，
> 在受管電腦上最不會卡。真的需要 PNG 再回頭處理 Playwright。

## 2. 安裝

在 Claude Code 裡輸入這兩行：

```text
/plugin marketplace add cathrynlavery/diagram-design
/plugin install diagram-design@diagram-design
```

然後**手動打開自動更新**：`/plugin` → **Marketplaces** → 選 **diagram-design** → **Enable auto-update**。

> ⚠️ **Claude Code 對第三方 marketplace 預設關閉自動更新。**
> 不開的話你會永遠停在安裝當天那個版本，而且**不會有任何提示**。
> 這正是 [README.md](../README.md)「文件的物理形態」那條原則的又一個例子：
> **壞掉後不會報錯的東西，要主動換成會報錯的。**

### 驗證

1. `/plugin` 看得到 `diagram-design` 且有版號
2. 在對話裡打 `/diagram-design` —— 應該跳出 `diagram-design`、`export-diagram`、`import-mermaid`、`import-drawio`、`profile` 這幾個
3. 直接說「畫一張這個專案的架構圖」，應該產出一個 `.html`，瀏覽器開得起來

## 3. 品牌化：讓圖看起來像你們家的

裝完是通用配色。要它長得像你們的產品／文件，跑一次 onboarding：

> 「讀 `<你們的網站網址>`，把品牌顏色與字型存成 profile」

它會抓配色與字型，存成 client profile。之後產的圖都會套用。

| 位置 | 內容 | 更新時會不會被蓋掉 |
|---|---|---|
| `~/.diagram-design/profiles/` | 存下來的品牌 profile | **不會**，套件更新後仍在 |
| 專案裡的 `.diagram-design` 標記檔 | 讓這個專案固定用某個 profile | **不會** |
| 套件內的 `references/style-guide.md` | 預設風格 | ⚠️ **會**被更新覆蓋，不要直接改它 |

管理指令：`/diagram-design:profile`（存、載、看、改、重設、刪）。

## 4. 基本用法

**不用背指令**，直接用自然語言講就會觸發：「畫一張 XX 的流程圖」「這段架構畫成圖」。
需要精確控制時才用 slash command：

| 指令 | 做什麼 |
|---|---|
| `/diagram-design:diagram-design` | 明確叫出主流程 |
| `/diagram-design:import-mermaid <檔>` | 把 Mermaid 重畫成圖（見第 5 節） |
| `/diagram-design:import-drawio <檔>` | 把 draw.io 重畫成圖 |
| `/diagram-design:export-diagram <html檔>` | 把產好的 HTML 轉成 `.svg` / `.png`（見第 6 節） |
| `/diagram-design:profile` | 管理品牌 profile |

### 四個轉盤

產圖與匯入都吃這四個參數。**先想清楚圖要貼到哪裡，四個轉盤就定了。**

| 轉盤 | 選項 | 預設 | 怎麼選 |
|---|---|---|---|
| `--format` | `html` / `svg` / `png` / `html+png` | `html` | 只要自己看 → `html`。要貼進簡報 → `png` |
| `--size` | `doc-inline` `doc-wide` `slide-16x9` `slide-4x3` `social-og` `social-square` `print-a4-landscape` `print-letter-landscape` `fit` | `doc-inline` | 貼進投影片 → `slide-16x9`（1280×720，輸出 2560×1440） |
| `--detail` | `faithful`（≤24 節點）／`balanced`（≤12）／`simplified`（≤7） | `balanced` | 給人看的簡報 → `simplified`；技術文件存查 → `faithful` |
| `--audience` | `engineer` / `mixed` / `executive` | `mixed` | 只影響**用字**，不影響節點數量 |

> **尺寸會連動字級。** `slide-16x9` 的節點名是 16px 而不是 12px ——
> 所以同一張圖換到投影片尺寸會**放不下**。那不是 bug，是尺寸轉盤在告訴你**細節轉盤開太大**。
> 正解是把 `--detail` 降一級，不是把字縮小。

## 5. ⭐ 把 Mermaid 轉成看得懂的圖

### 5.1 為什麼要轉

Mermaid 是 AI 產圖的預設輸出 —— 你不指定，它幾乎一定給你 Mermaid。這在**版控與被 AI 讀取**這兩件事上是對的選擇：純文字、diff 得出來、`grep` 得到。

但它有兩個結構性的問題，而且**兩個都不會報錯**：

| 問題 | 症狀 |
|---|---|
| **版面是 render 時算的** | 節點一多就自動排成一團，連線互相穿過。你能改的只有 `TD`／`LR` 一個方向 |
| **看不到的地方等於不存在** | GitHub、Obsidian、VSCode 預覽外掛裡看得到；貼進 PowerPoint、Word、Slack、PDF 就只剩一坨程式碼 |

第二點跟 [README.md](../README.md)「文件的物理形態」描述的是同一種病：**在某個軟體裡才看得到的東西，換個地方就消失，而且沒有任何工具會告訴你。**

### 5.2 什麼時候「不用」轉

**多數時候不用轉。** 別把這節當成「Mermaid 要全部消滅」。

| 情況 | 怎麼做 |
|---|---|
| 圖是寫給 AI 或工程師看的、放在 `doc/` 或 README 裡 | **留著 Mermaid。** 版控友善、改起來便宜 |
| 圖會一直改 | **留著 Mermaid。** 轉出來的圖是產出物，改一次要重轉一次 |
| 要放進簡報、對外文件、要印出來 | **轉。** |
| 節點多到自動排版已經打結 | **轉。** |

> **判準**：這張圖是**要繼續改的原始碼**，還是**要交出去的產出物**？
> 前者留 Mermaid，後者轉。

### 5.3 怎麼轉

```text
/diagram-design:import-mermaid doc/流程.mmd --size=slide-16x9 --detail=simplified --format=png
```

吃 `.mmd`、`.mermaid`，以及 Markdown 檔裡的 ` ```mermaid ` 區塊。
一個 Markdown 檔裡有多張圖時，用 `--diagram N` 指定第幾張，或 `--diagram all` 全部各出一檔。

### 5.4 ⚠️ 它是「重畫」，不是「轉檔」

**這一小節是整份文件最容易踩的地方。**

它不會保留 Mermaid 的版面、主題、`classDef`、`style`、`linkStyle`、`:::class`。
它讀出的是**內容與結構**（有哪些節點、誰連到誰、方向是什麼），然後**從空白畫布重畫**。

三個直接後果：

| 後果 | 說明 |
|---|---|
| **你調過的顏色會消失** | 源檔的主題與樣式一律丟棄，換成 profile 的一個強調色 ＋ 灰階 |
| **節點會被刪掉** | `--detail` 是**上限**：`simplified` 最多 7 個節點。原圖 20 個節點就會被砍。這是刻意的，但你要知道它砍了 |
| **方向只是提示** | `TD`／`LR` 是參考，選定的圖型有自己的版面慣例，會覆蓋它 |

> **所以轉完一定要自己看過一次。** 尤其是被砍掉的節點裡有沒有你其實需要的那個。
> 圖出來很漂亮，但少了一個關鍵分支 —— 這個失敗形態不會報錯。

### 5.5 支援範圍

只支援四種 grammar：

| 支援 ✅ | 不支援 ❌ |
|---|---|
| `flowchart` / `graph` | `gantt` |
| `sequenceDiagram` | `pie` |
| `stateDiagram-v2` | `journey` |
| `erDiagram` | `mindmap`、`gitGraph`、`timeline`、`quadrantChart` … |

不支援的 grammar 會**直接失敗並印出原因**（extractor 回傳 exit code 2）——
這個至少會報錯，不是安靜壞掉。

還有三個上限，正常用不會碰到：來源 4 MiB、2000 個節點、5000 條連線。

> 不支援的類型不代表畫不出來 —— diagram-design **本身**有甘特圖、時間軸等 39 種圖型。
> 走不通的只有「從 Mermaid 自動匯入」這條路，直接叫它畫就好。

### 5.6 這條路不上網、也不執行你的圖

抽取器是純 Python，**不 render、不執行、不連網**，也不會去點 Mermaid 裡的 `click` 連結。
Mermaid 原始碼被當成**不可信的純資料**處理。

這件事值得寫下來：把圖貼到線上 Mermaid 編輯器轉圖，等於把內容送到外部服務。
**這條路沒有那個問題。**

## 6. 匯出 PNG / SVG

```text
/diagram-design:export-diagram 我的圖.html
```

在來源旁邊產出同名的 `.svg` / `.png`。兩者都是**只有圖本身**（頁首、摘要卡、頁尾會被丟掉），PNG 是**透明背景**，貼到任何底色都不會有白框。

| 格式 | 需要什麼 | 坑 |
|---|---|---|
| **SVG** | 零依賴 | 字型是用 Google Fonts 遠端 `@import`。**離線的 Illustrator、部分 Figma 匯入路徑、舊的 SVG 檢視器會換掉字型** —— 要像素級一致就用 PNG |
| **PNG** | Python 的 Playwright | 見下方防火牆警告 |

> ## ⚠️ Playwright 第一次啟動會跳 Windows 防火牆視窗
>
> Playwright 會啟動 Chromium，**Windows 防火牆會跳出「允許存取」視窗，
> 這個視窗必須由使用者手動點**，腳本處理不了。
> 如果組織原則鎖住了防火牆設定，可能要管理員介入才放得行。
>
> 卡住的話：**改用 SVG，或直接用瀏覽器截圖。** 不要為了 PNG 卡在這裡。

## 7. 踩坑清單

| 坑 | 現象 | 原因 | 解法 |
|---|---|---|---|
| **自動更新沒開** | 半年後還在用安裝當天的版本 | 第三方 marketplace 預設關閉自動更新 | 第 2 節，手動開一次 |
| **改了 `style-guide.md`，更新後不見了** | 調好的風格被還原 | 套件內檔案會被更新覆蓋 | 改用 profile（第 3 節），或照上游 README 做 editable install |
| **轉完少了節點** | 圖很漂亮但缺一個關鍵分支 | `--detail` 是節點數上限，超過就砍 | 提高 `--detail`，或先把 Mermaid 拆成兩張 |
| **轉完顏色全變了** | 原本調好的 `classDef` 沒了 | 這是重畫不是轉檔，源檔樣式一律丟棄 | 這是預期行為。要品牌色請走 profile |
| **投影片尺寸的圖擠爆** | 節點放不下、字被壓 | 尺寸預設會連動放大字級 | 降 `--detail` 一級，**不要縮字** |
| **PNG 匯出卡住** | Playwright 裝不起來或防火牆擋住 | 見第 6 節 | 改 SVG 或瀏覽器截圖 |
| **甘特圖匯入失敗** | exit code 2 | `gantt` 不在支援的四種 grammar 裡 | 別匯入，直接叫它畫甘特圖 |
| **SVG 在 Illustrator 裡字型跑掉** | 字型變成預設 | SVG 用遠端 Google Fonts | 用 PNG |

## 9. 另一個工具：archify —— 要圖對程式碼負責時才用

上游專案：https://github.com/tt-a1i/archify （MIT）
本文對照的版本：**2.16.0-dev.0**（2026-08-28 實裝驗證）

### 9.1 分界：輸入不同，責任也不同

| | **diagram-design** | **archify** |
|---|---|---|
| 你給它什麼 | 一張圖或一段描述、`.mmd`、`.drawio` | 一份型別化的 JSON 規格 |
| 圖能不能引用程式碼 | ❌ 沒有這個概念 | ✅ 每個節點最多引用 3 個位置（路徑＋行號） |
| 引用會不會被驗證 | — | ✅ **路徑與行號都對指定 commit 驗證**，錯了直接擋下不出檔 |
| 圖種 | 約 40 種 | 5 種：architecture／workflow／sequence／dataflow／lifecycle |
| 產出 | HTML／SVG／PNG | 單檔 HTML（約 700KB）；PNG 要在檢視器裡**手動**匯出 |

一句話：**要圖對程式碼負責時用 archify，其餘用 diagram-design。**

### 9.2 安裝

```bash
npx skills add tt-a1i/archify -g          # 裝進 ~/.agents/skills/，再連結進 Claude Code
node ~/.agents/skills/archify/bin/archify.mjs doctor   # 15 項自檢，要全過
```

> ⛔ **不要跑上游 README 裡的 `dsh plugin ...` 那條。** 那是 DeepSeek 整合，
> 是社群版不是官方，而且會把東西送到外部服務。核心功能完全不需要它。

前置需求只有 **Node ≥18** —— 這個移植包本來就要求它（收工 hook 是 Node 寫的），
所以**沒有帶進任何新的前置需求**。程式碼裡零個 `fetch`／`XHR`，165 個檔全是純文字，無二進位執行檔。

### 9.3 怎麼用

1. 讓 AI 照 `schemas/` 與 `examples/` 寫規格 JSON
2. `validate <type> <spec.json> --quality showcase --json` —— 跑到 0 錯 0 警為止
3. `deliver <type> <spec.json> <out.html> --quality showcase` —— 交付，會給規格與產出的 SHA-256

要用實據功能，規格裡還要填：

- `meta.repository`：GitHub 網址 ＋ **40 碼 commit SHA**
- 各節點的 `sources[]`：`path`、`line`、`end_line`、`label`
- 執行時加 `--repo-root <repo 路徑>`

產出的 HTML 裡每個節點會有**釘死那個 commit 的 GitHub 永久連結**，帶行號範圍。

### 9.4 ⚠️ 四個必須先知道的限制

| # | 限制 | 影響 |
|---|---|---|
| 1 | **實據功能只支援 GitHub** —— `meta.repository.url` 的正規式寫死 `^https://github\.com/...` | 私有的 GitLab／Bitbucket／自架 server **用不了它唯一的賣點** |
| 2 | **產出的 HTML 會連 Google Fonts**（`fonts.googleapis.com`＋`fonts.gstatic.com`），寫死在 `assets/template.html`，**沒有開關** | 圖的內容不會外流，但「有人開了這個檔」會對外產生請求。要放進 README 就**手動匯 PNG**，圖片沒有這個問題 |
| 3 | **版面格線很嚴，規則沒寫在文件裡** —— 欄距是不等距的（實測 132／80／130／70／125），同一個 lane 只有 `col 0→1`、`2→3`、`4→5` 放得下兩個節點 | 踩到只會看到 `nodes less than 8px apart`，看不出真正原因 |
| 4 | **中文標籤吃緊** —— 標籤寬 ≈ `6.5px × 單位 + 13px`，**一個中文字算兩單位** | 預設節點大約只裝得下 **6 個中文字**。標題要短，細節放 `sublabel` 與 `cards` |

> ⚠️ **繁體中文沒有對應的 `meta.locale`**（它只支援 `en` 與 `zh-CN`）。
> 正確做法是**省略這一欄**，authored 內容全部維持繁中，
> 但要知道檢視器的固定介面與 `<html lang>` 會是英文。

### 9.5 為什麼還是收了

驗證器是**真的會擋**，而且診斷可直接對症 —— 訊息裡會直接給 `labelAt` 的建議座標。
實測拿假路徑與超出檔案長度的行號各試一次，**兩種都被擋下不出檔**。

這件事 diagram-design 做不到，也不該由它做。兩者不是取代關係。

> ⚠️ **這一節的版本、星數與限制是 2026-08-28 的量測事實，不是要維護的現況。**
> 不要回頭改它，過期了就整段重寫並註明新日期。
