# 美術指南收為選配的第五份正本，接線預先惰性內建

**問題是什麼**

下游的一個遊戲專案在量產美術前，自己開了 `doc/ART.md`（風格方針、網格尺寸、繪製規矩、
特效分層、工具製程、自檢表），並把它當第五份正本接進五處分工表與 hook。
使用者要把這套寫法收回 kit：**不是每個 prototype 都需要強調美術風格，
但每個專案都該在開工時考慮過。**

**選了什麼**

| 決定 | 內容 |
|---|---|
| 定位 | **選配的第五份正本**。預設仍是四份；ART **不是規格正本**，數字要升級成規格得寫進 DESIGN（需授權） |
| 交付形式 | 骨架 `core/選配/doc/ART.md` ＋ 說明 `core/美術指南.md`。**放在 starter 外面**，`cp -r starter/.` 帶不走 |
| 預先內建的接線 | hook `TRIGGERS` 加 `doc/ART.md`、doc-sync 路由表加一列（標「有這份才適用」）—— **沒開 ART 時完全惰性** |
| 不預先內建的 | 五處分工表的那一列。接上時才加 |
| 讓「考慮過」落地 | starter 的 PLAN「素材需求與版權」加一格「要不要開美術指南：開／不開 —— 為什麼」；安裝檢查清單加一列 |

**為什麼這次可以有第五份 —— 跟 2026-09-12 那兩次拒絕的分界**

[分支模型那一則](2026-09-12-分支模型與發佈流程.md)與當天的 devlog 兩次以
「四份文件的分工是封閉的」拒絕第五份正本。那兩次被拒的都是**流程規則**
（分支慣例、commit body 規矩）—— 那類東西本來就不住在四份文件裡，住在 AGENTS 與 skill。

ART 不一樣：它是**一個內容領域的正本**，而且**翻閱時機跟 PLAN 不同** ——
PLAN 是排程或選型有疑問時翻，ART 是每次坐下來畫圖之前翻。翻閱時機不同就該分檔。
所以那兩則的結論依然成立，**不推翻**；這一則補的是「分工封閉」的適用範圍：
**封閉的是流程規則的去處，不是內容領域的數量。**

**為什麼接線要一半預先內建、一半不內建**

判準是**「留著的話，沒開 ART 的專案會不會被誤導」**：

- `TRIGGERS` 裡的 `doc/ART.md`：檔案不存在就永遠比對不到，**零症狀、零誤導**。
  而它正是接上時最容易漏的一步 —— 漏了的後果是「改 ART 不必回填」，**不會報錯**
- 路由表那一列：寫明「有這份才適用」，AI 讀到也不會以為要去建
- 分工表那一列：**會誤導**。表上列著一份不存在的正本，讀的人會以為它存在。
  跟 AGENTS「刪掉的列要真的刪掉」同一個理由

**為什麼連結檢查要改**

骨架裡指向 `DESIGN.md` 等同層檔案的相對連結，是寫給複製過去之後的位置，在 `core/選配/doc/` 底下是斷的。
直接把 `選配/` 排除掉的話，裡面真正寫錯的連結也會跟著被放過 ——
所以改成 `RESOLVE_AS`：照它在 `core/starter/` 裡的對應位置解析。
前提是 `選配/` 的目錄結構**鏡像 starter**，這條要守住。

**沒選的路**

| 沒選 | 為什麼 |
|---|---|
| **預設放進 starter** | 不需要的專案得刪檔＋改五處分工表＋改 hook＋改路由表，**漏一處不會報錯**，只會留下一份幽靈正本的痕跡。多數 prototype 用不到，讓多數人付刪除成本不划算 |
| **只寫規範、不附骨架** | 沒有可對照的形狀，每個專案長得不一樣；而下游專案已經證明了一份可用的形狀，丟掉可惜 |
| **ART 併進 PLAN 當一節** | 翻閱時機不同（見上）；而且尺寸表、自檢表會隨每張圖持續長大，日後拆出來要多搬一次 |
| **把下游專案那份原樣搬進 examples** | 含具名人物、商業遊戲參考與特定引擎細節。改寫 unity-道具掉落 的精簡虛構版，示範格式就夠 |
| **hook 加「有自產素材卻沒 ART 就提醒」** | 「有沒有自產素材」機械判斷不了。這是開工時的一次性判斷，放 PLAN 那一格 ＋ 安裝檢查清單 |

**如果錯了會怎樣**

- 多數專案其實都需要 ART → 症狀是 PLAN 那一格幾乎都填「開」。那就該改成預設內建
- 接上時還是漏了分工表 → 症狀是某份文件開頭的表少一列。`美術指南.md` 的接法清單有六步，
  若反覆漏同一處，考慮在 `連結檢查.py` 加「doc/ 有 ART.md 但分工表沒提到」的檢查
- ART 被當成規格正本在用 → 症狀是 DESIGN 的尺寸欄一直空著、大家都照 ART 的工作值做。
  骨架開頭與 `美術指南.md` 3.1 都寫了，但這條只能靠升報時有人問
