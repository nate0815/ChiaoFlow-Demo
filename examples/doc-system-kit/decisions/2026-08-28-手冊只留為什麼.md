# 手冊只留「為什麼」：與正本重複的內容一律換成一句話 ＋ 連結

**問題是什麼**

`README.md` 長到 650 行，是整個 repo 最長的檔案。逐檔比對後發現長度的來源
**不是「寫太多」，是「同一件事寫在兩處」** —— 正好違反手冊自己列的核心紀律。

| 病灶 | 量 |
|---|---|
| 與 `SKILL.md`／`starter/doc/TECH.md` 近乎逐字重複的表與 code block | 約 90 行 |
| 三個已有獨立正本的主題（被推翻的輪替歸檔、交棒封存、周邊工具選型） | 173 行 |
| 三處重複的索引表（頂部導覽、安裝那節、末節「怎麼裝怎麼用」） | 約 25 行 |

最諷刺的一處：手冊在「DESIGN 是唯一參照」那節寫著「規則本體寫在 `doc/DESIGN.md` 開頭，
`SKILL.md` 與 `CLAUDE.md` 只放指標」，**它自己卻複製了一份升報格式 code block。**

**選了什麼**

| 內容 | 去哪 |
|---|---|
| 與 `SKILL.md`／`TECH.md` 重複的四張表與升報 code block | 刪，改成一句話 ＋ 指向正本 |
| 交棒與封存（53 行操作性清單） | 新檔 `core/交棒與封存.md`（可選 SOP，與 Obsidian／MCP／Notion 同層） |
| 被推翻的「輪替歸檔」（53 行） | 併進 [2026-08-25-DEVLOG-拆檔.md](2026-08-25-DEVLOG-拆檔.md) —— 推翻它的那則決策 |
| 周邊工具的兩條選型判準、pptx skill 的否決理由、「內容不要離開你的機器」 | `extras/README.md`（原本只有 32 行，本來就該承載這些） |

結果：650 → 426 行。**論述一條都沒少**，少的是抄過來的那幾張表。

**為什麼被推翻的條文不是刪掉而是搬家**

「被推翻的不刪」講的是**不要讓判斷消失**，不是「不准換位置」。
搬到推翻它的那則決策旁邊，其實比留在手冊裡更容易被讀到 —— 半年後有人是為了
「當初為什麼決定拆檔」而點開那個檔的，舊做法就在同一頁往下捲。
搬移一字不改，所以不違反「只追加不改寫」。

⚠️ 但**仍然生效**的兩條原則沒有跟著搬：「不做定期精簡」與
「先量它什麼時候真的被讀，不要從體積直接推成本」留在手冊的「已知邊界」。
它們與拆檔無關，跟著搬會讓生效的原則被歸檔進歷史。

**⚠️ 跨檔章號這次真的咬到自己**

重排章節前先掃了一次，發現**五處外部檔案**用 `README §6`、`§10`、`§5.1` 指進手冊 ——
正好是手冊自己第五條護欄禁止的形式。不改就會在這次重排後安靜地指到別節。

還查到一個**今天就已經壞掉**的引用：`core/安裝.md` 寫「前置需求見 README 的『前置需求』」，
而手冊根本沒有這一節（內容在 `setup/README.md`）。**沒有任何工具報過錯。**

所以這次多做一件原本沒打算做的事：**連手冊內部的自我引用也一起拔掉章號**，
全部改寫成章節標題。護欄允許同檔內用章號，但這一份被外部引用的頻率太高，
章號一位移就是五個檔一起錯。

**代價**

想一次讀完全部設計理由的人，現在要多點兩個連結（`core/交棒與封存.md`、`extras/README.md`）。
接受 —— 這是「同一件事不寫在兩處」的必然代價，而重複的兩處一定會分岔。
