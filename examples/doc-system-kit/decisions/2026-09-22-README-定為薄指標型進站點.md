# README 定為薄指標型進站點，用骨架檔交付、不加裝置

**問題是什麼**

使用者把這套規則移植到別的專案，發現**不會產出 README**。查完確認是真的缺口，
而且形狀很特別：**README 在執行鏈上已經是一等公民，在產生鏈上完全不存在。**

| 執行鏈（有） | 產生鏈（沒有） |
|---|---|
| `doc-sync-check.mjs` 的 `TRIGGERS` 含 `README.md` | starter 沒有 README 模板 |
| `doc-sync/SKILL.md` 路由表有「檔案結構／上手方式／驗證指令變了 → `README.md`」 | `core/安裝.md` 全 6 節零次提及 |
| 衝突分流把 README 與 PLAN／TECH 同級處理 | `AGENTS.md` 147 行零次提及 |
| | 兩個範例都沒有 README |

結果是一個閉環漏洞：**專案根本沒有 `README.md` → 路由表那一列永遠不會被觸發
→ 也永遠不會有人被提醒。** 規則寫了，但沒有東西讓它開始生效。

順帶查到一處實質不一致：`core/README.md`「裝完之後長什麼樣」那棵目錄樹**沒有
`README.md`**，與手冊裡「README 留在根目錄當進站點」那句互相矛盾。已一併修掉。

**選了什麼**

| 決定 | 內容 |
|---|---|
| README 的形狀 | **薄・指標型**。必備三節：這是什麼／怎麼跑起來／文件在哪。選用一節：現在到哪了 |
| 規範正本放哪 | `.agents/skills/doc-sync/SKILL.md` 的「README 的必備章節」 |
| 交付形式 | `core/starter/README.骨架.md` —— **刻意不叫 `README.md`** |
| 與 TECH 的分界 | README =「第一次怎麼跑起來」；TECH「30 秒驗證」=「確認它還沒壞」 |
| 機制 | **沒有裝置。只有文字護欄 ＋ 安裝檢查清單一列** |

**為什麼骨架檔不叫 `README.md`**

因為安裝第一步是 `cp -r starter/. <專案>/` —— 如果 starter 裡有 `README.md`，
它會**無聲覆蓋**專案既有的那份。不報錯、不問你，內容就沒了。
那正是這一包一直在治的第三種病：**壞掉了，但不會有任何東西告訴你。**

換個檔名，`cp` 就碰不到它。代價是多一個手動步驟（照它建、然後刪掉），
而漏做那一步的症狀是**看得見的**（專案沒有 README，clone 下來一眼就知道）。
**用一個看得見的漏做，換掉一個看不見的覆蓋。**

檔名用中文也是刻意的：starter 底下其餘全是英文檔名，這一份混在裡面
一眼看得出「它不是最終檔、要被處理掉」。

**為什麼規範正本放 SKILL.md，不放骨架檔**

骨架檔用完就刪，所以章節清單不能只存在於它裡面 —— 刪掉之後規則就跟著消失了。
放 SKILL.md 的理由是**時機**：那是 AI 回填時才載入的檔，正好是需要這條規則的時刻，
而且路由表那一列就在旁邊。`AGENTS.md` 與手冊都只放指標，不複製第二份。

**為什麼 README 要薄**

寫厚就會跟 `doc/TECH.md` 重疊（檔案清單、驗證指令、參數表），而**兩份分岔的時候
不會有任何工具報錯** —— README 會慢慢變成一份看起來很完整、但已經不對的說明。

判準寫進了規範：**「這段內容過期了，誰會先發現？」**
答案是「改程式的人」→ 該在 `doc/TECH.md`，README 只放連結。

**沒選的路**

| 沒選 | 為什麼 |
|---|---|
| **starter 直接放 `README.md`** | `cp -r` 會無聲覆蓋既有 README。最自動，但壞法沒有症狀 |
| **完全不放檔案，只寫規則讓 AI 產生** | 沒有可對照的正本，每個專案長得不一樣。而且使用者遇到的問題正是「AI 不會自己想到要做」 |
| **完整型 README（含檔案結構、驗證表、FAQ）** | 直接違反「同一件事不寫在兩處」。對外部讀者友善，但代價是兩份一定會分岔 |
| **在 `doc-sync-check.mjs` 加「README 不存在就提醒」** | 依本包自己的判準 —— **一個裝置要留下來，得先說得出它擋掉了什麼** —— README 不存在是看得見的症狀，說不出來。內容腐爛那一半已經被 `TRIGGERS` ＋ 路由表涵蓋 |
| **把 `README.md` 加進 hook 的 `GATE`** | `GATE` 是回填閘門，README 是**被回填的對象**。加進去等於「改 README 就能放行不寫 DEVLOG」 |
| **另開一支 README 章節檢查腳本** | 手動跑的腳本會被忘記。真要機制化，該跟 `core/工具/連結檢查.py` 一起進 CI，不是再加一支 |

**範例怎麼處理 kit 自己是例外這件事**

`examples/unity-道具掉落/README.md` 是填滿的薄 README 範本。
但 ChiaoFlow 自己的 README 是五百多行的手冊，**不是薄指標型** ——
因為對這個 repo 而言 README 就是產出物本身。

`examples/doc-system-kit/README.md` 直接寫明這是例外、為什麼是例外、
一般專案照哪一份的形狀。**照本包「明寫已知邊界」的慣例，這比硬生一份假的薄版誠實。**

**如果錯了會怎樣**

- 三節不夠用 → 症狀是大家都在 README 加第四、第五節。那代表少規範了一節，補進 SKILL.md 就好
- 骨架檔一直沒被刪 → 症狀是專案裡同時有 `README.md` 與 `README.骨架.md`。
  這是看得見的，安裝檢查清單也有一列在問
- 薄 README 讓外部讀者找不到東西 → 症狀是有人問「這個怎麼跑」。
  那代表「怎麼跑起來」那一節寫得不夠具體，不是 README 該變厚
