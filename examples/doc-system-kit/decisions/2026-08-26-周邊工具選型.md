# 周邊工具（圖／簡報）的選型：兩條判準否決掉最強的候選

**選了什麼**

| 用途 | 選定 | 授權 |
|---|---|---|
| 產圖、把 Mermaid 轉成正式圖 | **diagram-design** | MIT |
| 做整份簡報（主線） | **frontend-slides** | MIT |
| 做整份簡報（要進版控時） | **Marp** | MIT |

三者都以**外掛／`npx`** 安裝，不需要本機管理員權限。

**為什麼判準只有兩條**

這個工具包的存在目的是**傳給協作者或網友**，而他們多半也在受管電腦上。
所以「好不好用」不是第一順位：

| 判準 | 不過會怎樣 |
|---|---|
| **授權能不能傳給別人** | 在說明文件裡叫別人裝一個授權要另外讀的東西，等於把問題丟給下一個人 |
| **受管電腦裝不裝得起來** | 沒有本機管理員權限就裝不了外部執行檔。為了一張圖跑申請流程，這條路實務上不會被走完 |

**排除的方案**

| 方案 | 為什麼排除 |
|---|---|
| **Anthropic 官方 pptx skill** | 兩條判準各否決一次：授權是 Proprietary；需要 LibreOffice（`soffice`）與 Poppler（`pdftoppm`）兩個外部執行檔。⚠️ **它產的是真正可編輯的 pptx，那是其他方案給不了的** —— 代價落在錯的地方，不是東西不好 |
| **reveal.js / Slidev** | 需要 build step 或 dev server，跟「零安裝」衝突。frontend-slides 的單檔 HTML 已涵蓋多數需求 |
| **zl190/md-slides** | Marp CLI 的薄包裝，可選功能要 LaTeX（約 4GB）或 Gemini API key。直接用 Marp |
| **線上簡報產生器（Gamma 等）** | 要把內容貼上外部網站，內部資料先天不通 |
| **PlantUML 當產圖主線** | 預設的本機算圖要 Java ＋ Graphviz（受管電腦沒有也裝不了）；改用伺服器模式則要自己填網址，填公開伺服器等於把圖送到外部伺服器 |

**⚠️ 一個沒被判準擋掉、但要寫下來的限制**

排除官方 pptx skill 的代價是：**這套組合產不出可編輯的 `.pptx`。**
Marp 的 `--pptx` 每頁是一張預先算好的背景圖，開得起來但字改不了；
`--pptx-editable` 是實驗性的，而且又要 LibreOffice。

所以「對方要拿去自己改字」這個需求**沒有被解決** ——
遇到時的誠實答案是回去用 PowerPoint，讓 AI 幫忙寫內容而不是產檔案。
記在 [../../../extras/簡報/製作.md](../../../extras/簡報/製作.md) 第 1 節的路線 C。

**這批工具刻意不做自動化裝置**

A 組（文件體系）有 Stop hook 與權限規則，是因為「文件落後於程式」**每天都在發生**。
B 組是一次性產出，做完就結束 —— 裝閘門沒有東西可以擋。
判斷寫在文件裡就夠了，不需要機制。
