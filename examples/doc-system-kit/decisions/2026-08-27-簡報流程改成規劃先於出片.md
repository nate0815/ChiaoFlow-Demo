# 簡報流程改成「規劃先於出片」，並自己寫一支大綱轉 pptx 的腳本

> ⚠️ **2026-08-28 部分修訂**：本則的**三道閘門仍然生效**，但「出片順序」那一段已被
> [2026-08-28-簡報流程定案為五階段](2026-08-28-簡報流程定案為五階段.md) 改掉 ——
> 視覺改成在整合成 pptx **之前**。本則以下的內容一個字都沒改，那是當時的判斷。

**問題是什麼**

實際做過幾份簡報之後，同一組症狀每次都出現：開場沒把「這場要對方回答什麼」講明確、
無效資訊比預期多、整份做完之後還要再修一輪。

一開始的診斷是「字太多」。實測之後推翻了：一份 28 頁的簡報逐頁刪字**只省了 5%**。
真正的原因是那 28 頁是為「完整導覽」寫的，而實際場合是「10 分鐘的提案」——
**場合沒有先被定義下來**，所以沒有任何一頁砍得掉。

**選了什麼**

| | |
|---|---|
| 流程 | 場合卡 → 逐頁大綱表 → 密度檢查 → **出 pptx** →（要上台才另出 HTML） |
| 人審點 | **只有一個：逐頁大綱表**（純文字階段，改一頁的成本是刪一列） |
| 正本 | 大綱 `.md` 是規劃期的正本；**出片後改 pptx，不回頭改大綱**（單向） |
| 出片工具 | 零安裝路線用 PowerPoint 自己的大綱匯入；要圖與講者備忘走自寫的 `outline-to-pptx.py` |

判準是「**閘門要卡在改起來還便宜的地方**」。原本的流程只有成品那一格有檢查點，
所以每次都在最貴的位置付錢。

**為什麼自己寫腳本，而不是裝現成的 skill**

2026-08-27 掃了一輪專門產 pptx 的工具，用的還是同一組兩條判準
（授權能不能傳給別人／受管電腦裝不裝得起來）：

| 方案 | 為什麼排除 |
|---|---|
| **anthropics/skills 的 `pptx`** | 授權是 Proprietary（同一個 repo 其他 skill 是 Apache 2.0，這四個文件技能不是） |
| **tfriedel/claude-office-skills** | 817 ★ 但授權未標明，且要 LibreOffice ＋ Poppler ＋ Pandoc |
| **pptxgenjs**（npm、MIT） | 產得出可編輯 pptx，但**不套既有範本母片**，只能從零建版面 |
| **tristan-mcinnis/pptx-from-layouts-skill**（MIT） | 形狀正確（markdown → 套母片版型），但 23 ★ 太薄不當相依 —— **拿來當藍本** |

自己寫的腳本沒有授權問題，而且只依賴 `python-pptx` 一個純 Python 套件
（不需要 LibreOffice、不需要管理員權限）。

**⚠️ 更正了 2026-08-26 那則的兩處事實**

[2026-08-26-周邊工具選型](2026-08-26-周邊工具選型.md) 的選型結論**沒有被推翻**
（diagram-design／frontend-slides／Marp 都還是選定），所以那則維持 `status: 生效`。
但它有兩處敘述現在是錯的：

1. 它寫官方 pptx skill「需要 LibreOffice 與 Poppler 兩個外部執行檔」——
   **建 pptx 不需要那兩個**，它們只用在縮圖與檔案驗證這兩個可選步驟。
   擋掉它的是授權那一條，而授權自己就足以否決。
2. 它寫「這套組合**產不出可編輯的 `.pptx`**，這個需求沒有被解決」——
   **現在解決了。** 不通的是「HTML → pptx」這個方向，不是 pptx 本身；
   從**大綱**直接生是通的，而且零安裝就有一條。

理由寫錯比結論寫錯更難發現，所以留著這則更正，不去改舊那則的內文。
要追這件事就 `grep -rl 2026-08-27-簡報流程改成規劃先於出片 .`。

**這一輪仍然不做自動化裝置，但理由變了**

2026-08-26 那則寫「B 組是一次性產出，裝閘門沒有東西可以擋」。
這次的流程讓那句話沒那麼絕對了 —— 場合卡與大綱表**確實有東西可以擋**
（大綱沒過就不准出片），腳本的 `--strict` 已經是半個閘門。

還是先不做 skill，理由換成：**判準還沒被手動跑過足夠多次**，
不知道哪一條真的有效、哪一條只是好聽。列為待決問題（[../DEVLOG.md](../DEVLOG.md) §6）。
