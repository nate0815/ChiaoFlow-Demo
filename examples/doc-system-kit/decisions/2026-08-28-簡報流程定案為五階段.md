# 簡報流程定案為五階段，視覺在整合之前

> ⚠️ **這則是 [2026-08-27-簡報流程改成規劃先於出片](2026-08-27-簡報流程改成規劃先於出片.md)
> 的「部分修訂」，不是取代。**
> 那則的**三道閘門（場合卡／逐頁大綱／密度檢查）仍然完全生效** ——
> 被改掉的只有「出片順序」那一段。

**問題是什麼**

2026-08-27 那則決策把流程定成「規劃先於出片」，並選定
**先出 pptx 當工作稿、之後才另出 HTML**。實跑一份 25 頁的導覽簡報之後，
那個順序被推翻了 —— 原因不是規劃那三道閘門有錯，而是**「視覺」被放在錯的位置**。

當時的順序是：大綱 → 出 pptx → （選用）出 HTML 做視覺。
實際跑起來的問題：

| 症狀 | 根因 |
|---|---|
| 樸素 pptx 出完之後，視覺要另外做，等於出兩次 | 視覺被當成「pptx 之後的加值」，而不是「pptx 的輸入」 |
| 想把好看的 HTML 變成可編輯的 pptx，發現不通 | **HTML 的視覺是 CSS**，轉不成 PowerPoint 的形狀與文字框 |
| 交出去的最終形態不明確 | pptx 樸素、HTML 好看但改不動，兩份都不是「可以交的最終版」 |

**選了什麼**

五個階段，順序不能顛倒：

```
① 出大綱    場合卡 ＋ 逐頁大綱表（閘門一、二）
② 出內容    密度檢查（閘門三）。可選：出樸素 pptx 驗一次
③ 出視覺    風格探索 → 選定 → 產圖
④ 整合      帶視覺的 pptx —— 最終交付形態
⑤ 人工手修  在 PowerPoint 完稿
```

關鍵改動是**第 ④ 步**：新增 `themed-pptx.py`，它不做轉檔 ——
**讀同一份大綱、用 python-pptx 直接畫出**選定的視覺，
而文字仍然放在真正的 placeholder 裡，所以改得動、大綱檢視看得到。

**為什麼順序是這樣**

| 為什麼 | 說明 |
|---|---|
| 視覺不能比內容早 | 內容還在動的時候做視覺，每改一句話就要重跑；而且會誘使你用「好看」掩蓋「還沒想清楚」 |
| 整合不能比視覺早 | pptx 是**帶著選定的視覺**產出來的。先出樸素版再想視覺，等於出兩次 |
| 手修一定最後 | 出片是單向的。在 PowerPoint 動第一個字之後，重跑產生器會整份蓋掉 |

**沒選什麼**

- ⛔ **沒有做「HTML → pptx」的轉換。** 市面上的轉換工具產出的是每頁一張圖片，
  字選不起來、改不動 —— 對「人工手修」等於沒用。這個方向永久排除
- **沒有把 HTML 降級成純預覽。** 它仍然是階段 ③ 的產出，也是「要可分享網址」時的答案；
  只是**不再是**「好看的那一份」的唯一途徑

**連帶的四個發現**

| 發現 | 影響 |
|---|---|
| **字型只能用目標機器已有的** | 視覺常用的 Google Fonts 多數機器沒裝。這份 pptx 是要交給協作者改的，字型換掉版面就跑 |
| **配色要跟圖對齊** | 淺色系的圖放在暗底簡報上會像貼上去的白方塊 |
| ⭐ **圖的可讀性槓桿是節點數，不是畫布大小** | 一度想把圖的畫布加寬來讓文字變大 —— 方向錯了。archify 的 `composition/desktop-readability` 直接擋下並說明：整張圖還是要縮進同一個框，加寬只會讓文字**相對變小** |
| **`（…）` 是給自己看的註記** | 踩過的坑：`（封面不放條列）` 曾經真的印在 pptx 封面上，而且沒有任何提示 |

**資料夾也一併整理**

簡報相關的東西原本散在 `extras/` 底下三個位置（兩份 SOP ＋ 一個範本資料夾）。
收攏成 `extras/簡報/`：`README.md`（五階段索引）、`規劃.md`、`製作.md`、
`範本/`、`工具/`（五支腳本 ＋ 主題底圖）。

**這一版的交付終點是 Google Slides**，所以 5.4 節記下了匯入之後要檢查的兩件事：
中文有沒有掉字型、等寬的頁碼與標籤有沒有跑版。
