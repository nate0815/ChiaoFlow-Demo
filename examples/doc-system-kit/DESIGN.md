## 1. 設計目標

### 1.1 一句話說明

一套可以帶去任何專案的文件體系，讓文件不會落後於程式，也讓規格不會被實作反向侵蝕。

### 1.2 要驗證的假設 ⭐

| # | 假設 | 怎麼判定 |
|---|---|---|
| **H1** | 機械化的收工閘門，比「寫在規則裡靠人記得」有效 | 有沒有出現「commit 了程式但四份文件只同步了三份」 |
| **H2** | 把「為什麼」前移到 commit body，能讓回填從考古降級成搬運 | 回填一次的實際耗時 |
| **H3** | 拆檔 ＋ 反向連結，能取代手工維護的索引表 | 索引表移除後，「某決策當時在幹嘛」還查不查得到 |

## 2. 規格本體

### 2.1 四份正本的分工

| 文件 | 回答什麼 | 時態 | 維護方式 |
|---|---|---|---|
| `DESIGN.md` | **做什麼** | 現在式 | 就地改，**改動需授權** |
| `PLAN.md` | **為什麼選這條路** | 現在式 | 就地改 |
| `TECH.md` | **路是怎麼鋪的** | 現在式 | 跟著程式改 |
| `DEVLOG.md` ＋ 三個資料夾 | **什麼時候發生了什麼** | 過去式 | **只追加** |

**選配的第五份**：`ART.md`（**畫起來長什麼樣、怎麼畫**，現在式、就地改）。
有自產素材要量產才開，但**開工時一定要判斷過**。它不是規格正本 —— 尺寸要成為規格得寫進 DESIGN。

### 2.2 拆檔範圍

| 文件 | 拆？ |
|---|---|
| DESIGN / PLAN / TECH | **不拆**，維持單檔 |
| DEVLOG 的時序 entry / 決策 / 踩坑 | **拆**，各自一則一檔 |

理由見 [decisions/2026-08-25-DEVLOG-拆檔.md](decisions/2026-08-25-DEVLOG-拆檔.md)。

### 2.3 三層裝置

**規格是「每一層要達成什麼」，不是「用哪個裝置達成」** —— 裝置依工具而異。

| 層 | 要達成什麼 | Claude Code | Codex CLI |
|---|---|---|---|
| 權威 | 規格正本不能被 AI 單方面改寫，**放行必須經過人** | `permissions.ask`（跳確認框） | PreToolUse hook 硬擋 ＋ `doc/.design-unlock` 解鎖檔 |
| 觸發 | 改了程式卻想結束時擋下來，不依賴任何人記得 | `hooks.Stop` | `[[hooks.Stop]]` |
| 流程 | 回填路由表、衝突偵測、升報格式，平常不佔 context | `.claude/skills/`（stub） | `.agents/skills/`（正本） |
| **守則** | 給 AI 的工作守則，**只放指標不放規則本體** | `CLAUDE.md`（`@AGENTS.md` 匯入） | `AGENTS.md`（正本） |

**共用規格**：觸發層與流程層的內容**必須只有一份**，放在工具中立的 `.agents/` 底下。
兩種工具的 Stop hook 契約相同（stdin 給 `cwd` 與 `stop_hook_active`，
stdout 吃 `{decision:"block", reason}`），所以腳本一份服務兩邊。

**權威層是唯一允許不對稱的一層** —— Codex 的 PreToolUse 不支援「跳框問人」
（`"ask"` 解析得過但不生效），只能 allow／deny。解鎖檔是為了在硬擋之下
仍然留一個「人點頭」的出口。

> ⛔ 解鎖檔**必須在 `.gitignore` 裡**。被 commit 的話這層保護對所有人永久失效，
> 而且不會有任何症狀。

### 2.4 文件的物理形態

**任何壞掉後不會報錯的引用形式，要嘛換成不會壞的，要嘛換成會報錯的。**

| 形式 | 換成 |
|---|---|
| 跨檔章號 `§16.7` | 章節標題 `「不變式」` |
| `[[wikilink]]` | 相對路徑 Markdown 連結 |
| Dataview 表格 | frontmatter ＋ grep |

判準：**關掉 Obsidian、用記事本打開那個檔，看不到的東西 AI 也看不到。**

### 2.5 分支與發佈

兩條長命分支，其餘短命。**規則正本在 [../../core/starter/AGENTS.md](../../core/starter/AGENTS.md)
的「分支與發佈」**（那一份會被複製進下游專案），本節只定規格層次的三條。

| 規格 | 內容 |
|---|---|
| **長命分支只有兩條** | `main` 開發、`stable` 已發佈。不設 `develop` 與 `release/*` |
| **試玩分支是一次性的** | `demo/*` 不合回任何地方，只做減法與封裝，打完 tag 就刪 |
| **產出物不進 git** | build 走發佈平台，用 tag 與原始碼對應 |

判準：**demo 分支上的 diff，如果拿掉之後 `main` 會少一個功能，那它就走錯分支了。**

> ⚠️ 本檔版本紀錄的 `v0.4` 是**文件內部版本**，與 git tag 的 `v0.x.y` **是兩套編號**，
> 不對齊也不該對齊。
