# 2026-09-22（週二）— Day 31：補上新專案的 README 規範

起點是使用者的回報：「把這個 repo 的文件規則移植到別的專案，發現不會自動產出 README。」
查證後確認是真缺口，而且形狀很值得記 —— 見下。

- 新增 [../../../core/starter/README.骨架.md](../../../core/starter/README.骨架.md)
  —— 薄指標型骨架，**刻意不叫 `README.md`**
- 規範正本落在
  [../../../core/starter/.agents/skills/doc-sync/SKILL.md](../../../core/starter/.agents/skills/doc-sync/SKILL.md)
  新增的「README 的必備章節」，路由表那一列從「變了才改」改成「不存在就建」
- [../../../core/安裝.md](../../../core/安裝.md)：複製清單加一列、新增 §2.1「建立根目錄的
  `README.md`」、完成檢查清單加一列，§2 標題改成「要替換的四處 ＋ 一份要建的」
- [../../../core/starter/AGENTS.md](../../../core/starter/AGENTS.md)：§2 加一段指標，
  §6.4 加「發佈時實跑一次 README 的『怎麼跑起來』」

  補上與 README 的分界

- 修掉一處實質不一致：`core/README.md`「裝完之後長什麼樣」那棵樹**原本沒有 `README.md`**
- 範例補了兩份 README，`examples/README.md` 的層級樹補上 README 的位置

**決策**

- [README 定為薄指標型進站點，用骨架檔交付、不加裝置](../decisions/2026-09-22-README-定為薄指標型進站點.md)
  —— 關鍵取捨是**骨架檔刻意不叫 `README.md`**：用一個看得見的漏做（忘記建），
  換掉一個看不見的覆蓋（`cp -r` 無聲蓋掉既有 README）。

**卡在哪／踩到什麼**

- **規範正本該放哪卡了一下。** 骨架檔用完要刪，所以章節清單不能只住在裡面。
  最後放 `doc-sync/SKILL.md` —— 理由是**時機**：那是 AI 回填時才載入的檔，
  正好是需要這條規則的時刻。跟 2026-09-12 分支規範那次「正本放 AGENTS.md」
  是同一種判斷：**看誰在需要它的時候讀得到。**
- **差點自己製造一個壞連結。** `AGENTS.md` 裡原本寫成指向 `README.md` 的 markdown 連結，
  但 starter 底下那份還不存在 —— `連結檢查.py` 會報一條永遠修不好的壞連結。
  改成 code span。**這一包自己的工具抓到了自己的錯，算是那支腳本的一次自證。**

**這一輪刻意沒做的事**

沒有動 `doc-sync-check.mjs`。README 不存在是**看得見的症狀**（clone 下來一眼就知道），
依本包自己的判準 ——「一個裝置要留下來，得先說得出它擋掉了什麼」—— 說不出來。
內容腐爛那一半，`TRIGGERS` 含 `README.md` ＋ 路由表本來就涵蓋了。

**驗證跑了什麼**

- `python core/工具/連結檢查.py .` → 71 個 .md，真正壞掉 **0 條**
- 端到端模擬移植：在暫存 repo 先放一份既有 `README.md`，`cp -r starter/. .` 之後
  **md5 一字未改** ✅ —— 這條是整個設計的核心，一定要驗
- 骨架檔的六個相對連結在**複製之後**全部指得到 ✅
- hook：乾淨工作區 `exit=0` 無輸出；改 `README.骨架.md` 也放行（不在 `TRIGGERS`）✅

**下一步**

1. 使用者拿這一版重跑一次移植，確認 §1 → §2.1 → §5 走下來真的會產出 README
2. 若「現在到哪了」那節在實際專案裡常被留空，考慮從選用降成刪掉

**這一輪最值得記的一件事**

> ⭐ **一條規則可以「寫好了、也被機制認得」，卻因為沒有東西讓它開始生效而永遠不觸發。**

README 在執行鏈上已經是一等公民 —— hook 的 `TRIGGERS` 認得它、路由表有它、
衝突分流也把它跟 PLAN／TECH 同級處理。缺的只有**產生鏈**：沒有模板、沒有安裝步驟、
沒有範例。於是專案根本沒有 `README.md`，那三個機制就一次都不會被觸發。

這跟前面那三次「安靜通過」是同一個家族，但**更早一步**：
前面那些是裝置被觸發了卻放行，這一次是**裝置根本等不到它要檢查的東西出現**。

> 查缺口時要問的不只是「規則寫了嗎」，還有「**這條規則的觸發條件，有誰負責讓它成立？**」
