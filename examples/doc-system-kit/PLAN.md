## 3. 核心判斷 ⭐

**這套東西的價值在於 AI 讀得到文件。**

所有其他決定都是這一條的推論：為什麼不拿 Dataview 當正本（AI 讀到零筆）、
為什麼不用 wikilink（AI 只能猜路徑）、為什麼 Obsidian 只能是可選閱讀器
（不能有「只在某個軟體裡才成立」的內容）。

如果這個判斷錯了 —— 例如文件其實主要是給人看的 —— 那 L2 那層的限制就過度了。

## 4. 架構：三層

| 層 | 內容 | 依賴 |
|---|---|---|
| **L0 基礎**（必要） | 四份正本 ＋ 三個資料夾、frontmatter、相對路徑連結、三層裝置 | 只要 git ＋ grep |
| **L1 閱讀增益**（選用） | 反向連結、關係圖、改名自動更新 | Obsidian 內建，零外掛 |
| **L2 視圖**（慎入） | Dataview、Bases | 外掛，只做人看的視圖 |

## 11. 已排除的技術路線

| 路線 | 為什麼排除 | 什麼條件下會重新考慮 |
|---|---|---|
| pre-commit git hook | `.git/hooks/` 不進版控、換機器要重裝，且 commit 當下被擋很煩 | —— |
| 讓 hook 自己改文件 | hook 只該做判斷與擋。內容由 AI 在對話裡寫，人看得到也能當場否決 | —— |
| `.ps1` 或 `.sh` 寫 hook | `.ps1` 在受管企業環境常因未簽章不能跑，`.sh` 在 Windows 依賴 Git Bash。Node 兩邊都通 | —— |
| 手工維護 DEVLOG 索引表 | 會腐爛。拆檔後 `ls` ＋ frontmatter 就是索引，不會腐爛 | 沒有 Obsidian 且無法拆檔時 |
