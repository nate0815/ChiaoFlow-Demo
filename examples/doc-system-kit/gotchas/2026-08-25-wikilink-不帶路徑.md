# `[[01]]` 在 Obsidian 點得動，在 GitHub 上是四個字元的純文字

**現象**

Notion 匯入產生的連結長這樣：

```
[[01]]
```

Obsidian 裡點得動。GitHub 的 blob 頁面上它就是純文字，VSCode 裡也點不開，
AI 讀到之後只能自己去 glob 猜哪個檔叫 `01`。

**原因**

wikilink **只有名字，沒有路徑**。Obsidian 之所以解得開，是因為它在背景維護
一份全 vault 的檔名索引，加上一套解析規則（同資料夾優先 → 最短路徑 → 其他）。
**那份索引和那套規則只存在於 Obsidian 內部。**

目前檔名剛好唯一所以還猜得中。等 `2027年/01.md` 出現，
`[[01]]` 對 Obsidian 以外的任何工具都是歧義的 —— 而且不會報錯。

**同源的第二個坑**：就算關掉 wikilink，`New link format` 若選成
`Path from vault folder`，產生的 `decisions/xxx.md` **長得跟相對路徑一模一樣
但語意不同**（從 vault 根算）。Obsidian 正常，GitHub 解成當前資料夾底下 → 404。

**解法**

Obsidian 設定 → 檔案與連結：

1. **Use [[Wikilinks]] 關閉**（`app.json` 的 `useMarkdownLinks: true`，鍵名方向與 UI 相反）
2. **New link format 選 `Path from current file`**（`newLinkFormat: "relative"`）

換掉之後功能一項都不少：反向連結、關係圖、改名自動更新引用**全部照常運作**，
而 AI、GitHub、編輯器都解得對。完整四項設定見 [../../../core/Obsidian環境.md](../../../core/Obsidian環境.md)。

⚠️ 既有 wikilink 要轉換時，**圖片檔名帶空格的要 URL 編碼**：
`![[image 1.png]]` → `![](image%201.png)`，否則圖是裂的。
