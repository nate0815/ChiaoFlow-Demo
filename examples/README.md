# examples/ — ChiaoFlow Core 裝起來實際長什麼樣

裝完 [../core/安裝.md](../core/安裝.md) 之後，`doc/` 會長成這個樣子。
兩個範例，都可以直接在 Obsidian 開起來點點看。

| 範例 | 內容 | 用途 |
|---|---|---|
| [unity-道具掉落/](unity-道具掉落/) | 一個 Unity 小功能，內容是虛構的 | 看格式怎麼填（**含 [README.md](unity-道具掉落/README.md) 進站點範本**、選配的 [ART.md](unity-道具掉落/ART.md) 美術指南） |
| [doc-system-kit/](doc-system-kit/) | 這個 repo 自己，**內容全部真實** | 看真實的決策鏈長什麼樣 |

---

## ⛔ 這兩個資料夾都不要複製

要複製到你專案裡的是 [../core/starter/](../core/starter/)，**不是這裡的任何一個資料夾**。

| | |
|---|---|
| `../core/starter/` | ⭐ **要複製的東西** —— 四份正本的空骨架 ＋ 三層自動化裝置 |
| `unity-道具掉落/` | 虛構的範例，**看格式怎麼填**用的 |
| `doc-system-kit/` | 這個 repo 自己的真實紀錄，**看真實決策鏈長什麼樣**用的 |

複製這裡的資料夾過去，你會得到一份**別人專案的內容**，而不是空骨架 ——
而且它不會報錯，你要寫到一半才會發現裡面全是不相干的決策。

---

## ⚠️ 真實情況比這裡少一層

真實專案的 vault 根**就是** `doc/`，四份正本直接放在根目錄：

```
MyGame/
├── README.md        ← 對外進站點，與 doc/ 平行，不在裡面
└── doc/             ← vault 開在這裡
    ├── DESIGN.md
    ├── devlog/
    └── ...
```

這裡為了同時放兩個範例，多包了一層資料夾。**不要照抄這個結構。**

> ⚠️ **`README.md` 特別容易被擺錯位置。** 它在真實專案裡跟 `doc/` **平行**，
> 不是 `doc/` 的第五份正本 —— 讀者不一樣（它是給還沒碰過這個專案的人看的）。
> 這兩個範例資料夾裡各有一份 `README.md`，那是**示範內容**，位置以上面那棵樹為準。

---

## 該看什麼

裝了 Obsidian 的話，這三件事點開才看得到：

1. **反向連結面板** —— 開 [doc-system-kit/decisions/2026-08-25-DEVLOG-拆檔.md](doc-system-kit/decisions/2026-08-25-DEVLOG-拆檔.md)，
   右側會列出所有提到它的 entry 與其他決策。**這取代了手工維護的索引表。**
2. **決策的推翻鏈** —— 開 [unity-道具掉落/decisions/2026-08-20-道具資料用-JSON.md](unity-道具掉落/decisions/2026-08-20-道具資料用-JSON.md)，
   frontmatter 的 `status` 是 `已推翻`，內文一個字都沒改。推翻它的那則用 `supersedes` 指回來。
3. **關係圖（Graph view）** —— 看得出哪些決策是樞紐、哪些筆記是孤島。

沒裝 Obsidian 也沒關係 —— 用記事本打開任何一個檔，看到的內容完全一樣。
**這正是重點**：這些就是普通的 `.md`。

## 不用 Obsidian 也能查

```bash
ls doc/decisions/                              # 全部決策（日期＋標題都在檔名裡）
grep -L "status: 已推翻" doc/decisions/*.md    # 只列還生效的
grep -rl "2026-08-20-道具資料用-JSON" doc/     # 哪些檔提到這則決策
```

**檔名就是 ID，不需要編號，也不需要索引表。**
